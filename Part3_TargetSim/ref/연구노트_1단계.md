## 목적

1. 과제 명세 1-(1) 표적 구조체를 정의한다.
   - 표적 최대 10개, 표적별 기동 최대 30개
   - 초기 위치는 위도·경도·고도, 속도는 동체 Heading 방향 속도 V_heading
   - 기동 정보는 Gravity Value, TurnType(0 없음 / 1 Roll / 2 Yaw / 3 Pitch), StartTime, EndTime
2. 궤적 모의에 쓸 좌표변환·행렬 코드를 믿고 쓸 수 있게 만든다.
   - 참고 소스 코드를 검토해 문제를 찾고, 코딩 규칙과 MISRA C:2023 에 맞춰 다시 작성한다.

## 방법

### (1) 참고 소스 코드 검토 후 재작성 (`matrixCalcLib_JH`, `CoordinateTransform_JH`)

- WGS84 상수: 정의값 a = 6378137 m, 1/f = 298.257223563 에서 f, b, e², e'² 를 식으로 유도했다.
- ECEF → LLA: Bowring 폐형식(반복 없음), 경도는 atan2, 극점(p < 1e-9 m)은 따로 분기했다.
  고도는 p·cosφ + z·sinφ − a·√(1 − e²·sin²φ) 로 구해 고위도에서도 발산하지 않는다.
- 역행렬·연립방정식: 부분 피벗 Gauss-Jordan, 특이하면 `MAT_ERR_SINGULAR` 를 돌려준다.
- 행렬식: 부분 피벗 LU 로 1~9차를 푼다.
- 좌표계 규약을 헤더에 명시했다.
  - Body: x 전방, y 우현, z 하방 / NED / ENU / Antenna: x 보어사이트, y 우측, z 하방
  - 방위각 az 는 우측이 (+), 고각 el 은 상승이 (+), 자세각 회전 순서는 ZYX
  - DCM 은 정규직교이므로 역변환은 전치
- API: 출력 포인터 + 상태 코드 반환, 입력은 const, NULL 검사, 출력과 입력이 같은 객체여도 안전하게 했다.
  (예외: `f_Mat_Load` 는 원소 배열이 출력 행렬 내부를 가리키면 먼저 0 으로 지워 입력이 사라진다.)
- LLA 변환과 자세각 입력은 구조체(`ST_CoordLla`, `ST_CoordAtt`)로 받아 인자 순서 실수를 줄였다.
  (참고 코드는 `(Lon, Lat, Alt)`, `(Roll, Yaw, Pitch)` 순서라 구조체 멤버 순서와 달랐다.)
  단 NED↔ECEF 계열 함수의 기준 위경도는 여전히 `refLat, refLon` 스칼라 두 개다.
- 규칙: 값을 반환하는 함수마다 return 하나, typedef 형만 사용, 함수형 매크로 대신 static inline,
  Core 표준 헤더는 `<math.h>` 와 `<stddef.h>` 뿐, 라이브러리 안의 printf 제거.

### (2) 표적 구조체 (`TargetSim_JH.h`)

| 명세 항목 | 구조체·필드 | 단위 / 비고 |
|---|---|---|
| 표적 수 (최대 10) | `ST_SimConfig.nTargetNum` + `st_Target[10]` | 1~10 |
| 표적별 기동 수 (최대 30) | `ST_TargetInit.nManeuverNum` + `st_Maneuver[30]` | 0~30 |
| 초기 위치 | `ST_TargetInit.st_InitLla` (lat, lon, alt) | rad, rad, m (WGS84 타원체고) |
| 속도 V_heading | `ST_TargetInit.headingSpeed` | m/s, 동체 x 축 방향 크기 |
| 초기 자세 | `ST_TargetInit.st_InitAtt` (roll, pitch, yaw) | rad, ZYX |
| Gravity Value | `ST_TargetManeuver.gravityValue` | G 배수, 부호가 회전 방향 |
| TurnType | `ST_TargetManeuver.enTurnType` | 0 / 1 / 2 / 3 (명세 값 그대로) |
| StartTime / EndTime | `startTime`, `endTime` | s, 구간은 [start, end) |
| 플랫폼 | `ST_PlatformInit` (위치, 자세, 속도) | 기동 없음 |
| 시뮬레이션 시간 / 간격 | `ST_SimConfig.durationTime`, `stepTime` | s |
| 한 시각의 상태 | `ST_TargetState` (simTime, ECEF 위치·속도, LLA 사본, 자세) | 1-(2) 대비 |

설계 결정

- 각도는 모두 rad, 길이 m, 시간 s 로 통일했다. 도↔rad 변환은 입력과 출력 경계에서 한 번만 한다.
- 속도는 크기 하나만 둔다. 방향은 자세각이 갖고 있으므로 자세와 속도 벡터가 어긋날 수 없다.
- 고정 배열 + 사용 개수 카운터로 표현했다. malloc 없이(Rule 21.3) 배열 인덱스 범위를 실행 중에 검사할 수 있다(Rule 18.1).
- gravityValue 의 부호는 동체축 오른손 법칙을 따른다: Roll(+) 우측 뱅크, Yaw(+) 우선회, Pitch(+) 기수 상승.
- 입력(const)과 시각별 상태를 분리했다. 상태의 기준은 ECEF(명세 1-(2))이고, LLA 는 출력과 다음 스텝의 NED 기준으로 함께 보관한다.
- 플랫폼은 기동이 없으므로 별도 구조체로 두어 기동 배열(960 B)을 뺐다.

## 한계

- 재작성본의 특이 판정 기준은 **피벗 절댓값 ≤ 1e-12 × max(1, 최대 원소 절댓값)** 이다 (행렬식 크기가 아니다).
  - 역행렬이 잘 정의되는 diag(1e6, 1e-7) 이나 [[1,2],[2,4.0000000000001]] 같은 준특이 행렬도 거부한다.
  - 원소가 모두 1e-12 이하인 행렬(예: 1e-13·I)은 조건수와 관계없이 거부한다.
  - 반면 행렬식이 1e-13 인 diag(1e-6, 1e-7) 은 통과한다. 3×3 DCM 용도에는 영향이 없다.
- `f_Mat_Det` 는 특이로 판정하면 `MAT_ERR_SINGULAR` 대신 `MAT_OK` 와 det = 0 을 돌려준다.
  같은 기준 때문에 정칙 행렬 diag(1e6, 1e-7) (참값 0.1) 도 0 으로 보고되어 진짜 특이 행렬과 구분되지 않는다.
- `f_Coord_WrapAngle` 은 −π 보다 아주 조금 작은 입력(−π 바로 아래 double)에서 +π 를 돌려주므로 실제 출력 범위는 [−π, π] 다.
- `f_Mat_Load` 는 row × column 곱을 범위 검사보다 먼저 계산한다. 비정상적으로 큰 INT32 를 넣으면 오버플로가 먼저 난다.
- LLA 변환은 입력 범위(위도 ±90° 초과, NaN)를 검사하지 않는다. 3×3 DCM 에도 9×9 행렬 구조체를 써서 계산 비용이 크다.
- 구조체 한계
  - 크기가 고정이다 (표적 2개만 써도 `ST_SimConfig` 는 10,320 B).
  - 같은 표적의 기동은 시간이 겹칠 수 없어 상승 선회 같은 복합 기동을 표현할 수 없다.
  - 속도 크기를 바꿀 방법이 없고, 표적 이름·종류 필드가 없어 인덱스로만 구분한다.
  - 플랫폼은 기동할 수 없다.
- 명세 3-(1) 은 참고 좌표변환 코드를 쓰라고 하므로, 발표에서 재작성한 이유를 따로 설명해야 한다.
