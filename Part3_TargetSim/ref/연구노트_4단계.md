## 목적

1. 3단계 실행기(`f_Tgt_InitSim` / `f_Tgt_StepSim`)를 UI 에서 돌려 표적·플랫폼의 LLA 결과를 보인다 (과제 명세 1-(3) 출력).
2. 사용자 결정 반영
   - 입력: 표적·기동을 편집할 수 있다 (표적 1~10 개, 표적마다 기동 0~30 개).
   - 출력: LLA 표, CSV 저장, 궤적 그림(5단계에서 당겨옴), 타이머 재생.
   - 규칙: Core 규칙을 UI 에도 준용한다 (형 목록, `st_`/`pt_`/`n`/`f_` 명명, `//` 주석, 단일 반환·else 종결).
3. Core 가 거르지 않는 비유한·비물리 입력(표적 속력 NaN, 플랫폼 속력 1e308 등, 3단계 한계)을 UI 에서 막는다.

## 방법

- 구조: 대화상자 한 개. 편집 모델은 문자열(`ST_TargetText`)로 두고 실행할 때만 숫자로 읽는다.
- 실행 흐름 (`f_RunScenario`)
  1. 문자열 → 숫자 (`f_Num_Parse`: 앞뒤 공백 제거, `0-9 + - . e E` 외 문자 거부, `strtod` 가 끝까지 읽어야 함, `isfinite`)
  2. UI 범위 검사 → `f_Tgt_ValidateConfig` → 실패하면 탐침으로 위치 찾기
  3. `memset(&st_Sim, 0)` → `f_Tgt_InitSim` → `f_Tgt_StepSim` × nStepNum, 표본은 `calloc` 버퍼에 복사
  4. 모든 표본·객체의 LLA·ECEF 위치·속도가 유한한지 확인 → 그림용 ENU 계산
  5. 모두 성공했을 때만 이전 결과 버퍼와 바꾼다. 실패하면 이전 결과를 그대로 보인다.
- UI 입력 범위 (명세에 없는 값이라 판단해 정함)

  | 항목 | 허용 범위 | 근거 |
  |---|---|---|
  | 간격 dt | 0.001 ~ 1 s, 1 ms 단위 | 하한 = Core `TGT_MIN_STEP_TIME`, 1 ms 단위라 시각을 %.3f 로 정확히 씀 |
  | 시간 D | 0.001 ~ 100000 s | D/dt 정수배·스텝 수 1~100000 은 Core 가 판정 |
  | 위도 / 경도 | ±89.9° / ±180° | 극점에서 NED 북이 정의되지 않음 |
  | 고도 | −1000 ~ 100000 m | 거대값 차단 |
  | 속력 | 플랫폼 0 ~ 3000, 표적 0.1 ~ 3000 m/s | 표적 속력은 ω = n·g/V 의 분모 |
  | Roll / Pitch / Yaw | ±180° / ±90° / ±360° | Yaw 270 과 −90 표기를 모두 받음 |
  | 기동 G | ±50 | 부호 = 회전 방향 |
  | 기동 시작·종료 | 유한 + dt 의 정수배 | 순서·범위·겹침은 Core 가 판정 |
  | 스텝당 회전각 | \|G\|·g/V·dt ≤ 30° | 중점법 현 오차와 비물리 선회 방지 |

- Core 오류 위치 찾기 (`f_LocateCoreError`): 판정은 Core 가 하고, 설정을 바꿔 다시 검증해 위치만 찾는다.
  - 모든 기동 수를 0 으로 둔 설정이 실패하면 전역 오류(시간 칸에 포커스, 시간/간격 비율 표시)
  - 아니면 표적 k 만 남기고 기동 수를 1, 2, … 로 늘려 처음 실패하는 (k, m) 을 찾는다. 해당 표적·기동을 선택하고 시작 칸에 포커스한다.
- 결과 표: 가상 리스트(`LVS_OWNERDATA`), 행 = 표본. 열은 CSV 와 같다 (스텝, 시각, 객체마다 위도·경도·고도).
- CSV: 가로형, ASCII, CRLF, 헤더 `step,time_s,platform_lat_deg,…,targetN_alt_m`. 서식은 표와 같은 함수(`f_FormatCell`)로 시각 %.3f, 위경도 %.9f°, 고도 %.4f m, `-0.0000` 의 부호 제거.
- 궤적 그림: 플랫폼 표본 0 기준 국지 ENU 수평면을 등축척으로 그린다. DCM 은 실행마다 한 번 만든다. 배경(격자·궤적·범례)은 비트맵에 캐시하고, 재생 때는 현재 표식과 진행 방향 화살표만 다시 그린다.
- 재생: 100 ms 타이머, 틱 수 기준 진행(배속 ×1/2/5/10/50/100). 슬라이더·표 선택·재생이 `f_ShowStep` 하나로 동기화된다.
- 검증 (솔루션 밖 임시 도구, 끝나면 삭제)
  - CSV 대조 하네스: Core DLL 을 직접 호출해 같은 서식으로 기대 CSV 를 쓰는 C 프로그램 (`/MD`, Release·Debug DLL 각각)
  - UI 자동화: Python ctypes 로 exe 를 띄워 컨트롤에 메시지를 보내고 결과를 읽음 (최종 88 항목), 화면 캡처
  - 정적 점검: MSBuild `/t:Rebuild` 경고 수, UI 파일 4개에 `cl /analyze`, 규칙 grep, 줄바꿈·BOM 바이트 확인
  - 코드 리뷰: 에이전트 4개가 관점별(MFC·Win32 정확성, 데이터 흐름·검증, 출력·그림, 코딩 규칙·리소스)로 읽고, 지적 상위 10건은 각각 다른 에이전트가 반박을 시도해 확인했다. 확인된 것과 명백한 규칙 위반을 고친 뒤 빌드·자동화를 다시 돌렸다.

  | 인자 없는 처리기 12 개가 `()` 로 선언됨 (규칙 3) | 확인 | `(VOID)` 로 변경 (MFC 재정의 함수 포함) |
  | `f_Ui_EnableCtrl` 인자를 const 로 둘 수 있음 | 판정 갈림 | 포커스 이동을 넣어 대화상자를 바꾸게 되어 비 const 유지 |
  | 북쪽 맨 위 눈금이 축 제목과 겹칠 수 있음 | 반박 (실제 글자 픽셀은 겹치지 않음) | 그대로 |
  | `POINT *pt_Line`, `FILE *pt_File` 은 구조체 포인터라 `st_`, 전역 `theApp` 은 접두어 없음, 반환값 버림에 `(VOID)` 누락 15 곳, 긴 CSV 경로가 상태 줄에서 잘림 | 미검증 (하위 우선순위) | 모두 수정: `st_Line`·`st_File`·`g_TargetSimApp`, `(VOID)` 추가, 상태 줄에는 파일 이름만 표시 |

- 규칙 점검: UI 파일 4개에 `int/double/char/bool/size_t/float/long/wchar_t` 0 건, `/* */` 0 건, doxygen 0 건, `m_` 는 MFC 소유 `m_pMainWnd` 만. 수정·신규 소스·프로젝트 12 파일 모두 CRLF·BOM 없음, `.rc` 의 `#pragma code_page(65001)` 가 첫 한글보다 앞.

## 한계

- 실행은 UI 스레드에서 동기로 돈다. 최악 부하에서 Release 0.58 s, Debug 1.66 s 동안 입력이 멈추고 진행 표시·취소가 없다.
- 입력 범위, 기동 시각의 dt 정수배 강제, 스텝당 회전각 30° 제한은 명세에 없는 판단이다. Core 로는 돌 수 있는 시나리오(예: dt 0.1 에 시작 10.05 s)도 UI 가 거부한다.
- 대화상자는 DPI 비인식 고정 크기(96 DPI 에서 약 1136×752 px)라 125 % 이상 배율에서 흐리고, 1366×768 화면에서는 넘친다.
- 그림은 플랫폼 초기 위치의 접평면(ENU)이라 수백 km 이상에서 왜곡된다. 진행 방향 화살표도 같은 기준으로 그려 그림 속 궤적과는 맞지만, 그 지점의 실제 방위(국지 북 기준)와는 자오선 수렴만큼 다르다. 범례가 왼쪽 위 궤적을 가릴 수 있고, 초기값이 같은 표적은 겹쳐 하나로 보인다.
- 재생 속도는 타이머 틱 수 기준이라 실제 시간과 약 10 % 어긋난다 (×1 2 s 에 18 스텝).
- CSV 경로 칸에 직접 쓴 경로는 확인 없이 덮어쓴다. 찾아보기(파일 선택) 대화상자와 디스크가 가득 차는 등 쓰는 도중의 실패는 자동화로 확인하지 않았다 (열기 실패 errno 2 만 확인).
- 결과 버퍼는 최악 약 134 MB (표본 116 MB + 그림 점 17.6 MB) 이고, 교체 순간에는 이전 결과와 함께 잡힌다.
- 자동화에서 `PrintWindow` 캡처는 가상 리스트 행을 그리지 못해 화면 캡처로 바꿨다. 화면 캡처는 창을 잠시 맨 앞에 두고 찍었다.
- 줄바꿈: 작업 트리는 CRLF 인데 루트 `.gitattributes` 는 `*.cpp`·`*.h` 를 eol=lf 로 정규화한다 (2·3단계와 같은 미결). `.rc` 는 `-text` 라 CRLF 그대로 커밋된다.
- 3단계 부록 A 결정 10 건은 여전히 사용자 확정 전이며, 4단계 입력 범위도 같은 상태다.
