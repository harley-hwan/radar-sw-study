## 2-1. 목적

1단계에서 만든 그릇에 값을 넣고, **0.1 초씩 시간을 흘려보내며 표적을 움직이는** 계산 엔진을 만든다.
과제 명세 1-(2) "표적 상태 정보 갱신" 에 해당한다.

여기가 과제의 핵심이다.

## 2-2. 좌표계 세 가지와 각각의 역할

표적을 움직이려면 서로 다른 세 개의 좌표계를 오가야 한다.
**왜 하나로 안 되는지** 를 이해하는 것이 이 단계의 절반이다.

### (1) 동체 좌표계 (Body) — "표적 자신 기준"

- x 앞, y 오른쪽, z 아래
- 표적이 움직이면 이 좌표계도 같이 움직이고 같이 돈다
- **쓰임** : 속도를 여기서 `(V_heading, 0, 0)` 로 간단히 표현할 수 있다

### (2) NED 좌표계 — "그 지점의 땅 기준"

- N(North) 북, E(East) 동, D(Down) 아래
- 표적이 서 있는 **바로 그 위치** 에서 본 동서남북
- **쓰임** : "북쪽으로 얼마, 동쪽으로 얼마" 처럼 사람이 이해하기 쉽다

여기서 중요한 점 : **NED 는 위치마다 다르다.**
서울에서의 "아래" 와 부에노스아이레스에서의 "아래" 는 지구 중심에서 보면 정반대 방향이다.
표적이 움직이면 NED 좌표계 자체가 조금씩 돌아간다.

### (3) ECEF 좌표계 — "지구 중심 기준"

ECEF = Earth-Centered, Earth-Fixed (지구 중심 · 지구 고정)

- 원점 : 지구 중심
- X 축 : 위도 0° · 경도 0° 방향 (아프리카 서쪽 바다 쪽)
- Y 축 : 위도 0° · 경도 90°E 방향 (인도양 쪽)
- Z 축 : 북극 방향
- 단위 m. 지표면의 점은 원점에서 약 6,378,000 m 떨어져 있다

**쓰임** : 지구와 함께 돌지만 **지구에 대해서는 고정** 이다. 어디에 있든 기준이 변하지 않는다.

### 왜 위치는 ECEF 에서 갱신하는가 (명세 요구이기도 함)

NED 에서 위치를 더해 나가면 문제가 생긴다.
표적이 1,800 m 서쪽으로 가면 그 지점의 "북쪽 방향" 이 원래와 미세하게 달라지는데,
좌표계가 바뀌는 와중에 좌표값을 계속 더하면 오차가 쌓인다.

ECEF 는 기준이 절대 안 바뀌므로 **덧셈이 안전하다.**

그래서 역할을 이렇게 나눈다.

```
방향 계산  →  Body / NED 에서   (사람이 이해하기 쉬움)
위치 누적  →  ECEF 에서         (기준이 고정이라 안전)
```

## 2-3. 공식 ① : 위도·경도·고도 → ECEF

### 식

```
N = a / √(1 − e² · sin²(위도))

X = (N + h) · cos(위도) · cos(경도)
Y = (N + h) · cos(위도) · sin(경도)
Z = (N · (1 − e²) + h) · sin(위도)
```

### 각 기호의 뜻

| 기호 | 뜻 | 값 |
|---|---|---|
| a | 적도 반지름 | 6,378,137 m |
| f | 편평률 (얼마나 납작한가) | 1 / 298.257223563 |
| b | 극 반지름 = a(1 − f) | 6,356,752.3142 m |
| e² | 제1이심률 제곱 = f(2 − f) | 0.00669437999 |
| h | 고도 | m |
| N | 묘유선 곡률 반지름 | 위치마다 다름 |

### N 이 무엇인가 — 가장 헷갈리는 부분

지구가 완전한 공이라면 반지름은 어디서나 똑같아서 `X = (a + h)·cos·cos` 로 끝난다.

그런데 지구는 타원체라 **위치마다 "부푼 정도" 가 다르다.**
그 보정값이 N 이다. 위도가 높아질수록(극에 가까울수록) N 이 조금씩 커진다.

숫자로 확인해 보면

```
위도  0° 에서  N = 6,378,137 m
위도 32° 에서  N = 6,384,141 m
위도 90° 에서  N = 6,399,594 m
```

차이가 최대 21 km 정도다. 20 km 떨어진 표적을 다루는 데 21 km 짜리 오차를 무시할 수는 없다.

Z 식에만 `(1 − e²)` 가 붙는 이유도 같다. 지구가 위아래로 눌려 있어서 **세로 방향만** 줄여 줘야 한다.

## 2-4. 공식 ② : ECEF → 위도·경도·고도 (Bowring 방법)

### 왜 어려운가

①번 식을 거꾸로 풀려고 하면, 위도를 구하는 데 N 이 필요하고 N 을 구하는 데 위도가 필요하다.
**서로 물고 물린다.** 그래서 한 번에 안 풀린다.

옛날 방식은 "대충 찍고 5 번 반복해서 맞춰 가기" 였는데,
반복 횟수가 고정이라 수렴이 보장되지 않고 극 근처에서 값이 튄다.

**Bowring 방법** 은 보조 각 하나를 도입해 **반복 없이 한 번에** 푸는 방법이다.
지구 근처(수백 km 이내)에서 밀리미터 수준으로 정확하다.

### 식

```
p = √(X² + Y²)                                (자전축까지의 거리)

경도 = atan2(Y, X)

θ = atan2(Z · a , p · b)                      (보조 각)

위도 = atan2( Z + e'² · b · sin³θ ,
              p − e²  · a · cos³θ )

h = p · cos(위도) + Z · sin(위도) − a · √(1 − e² · sin²(위도))
```

여기서

```
e'² = e² / (1 − e²) = 0.00673949674           (제2이심률 제곱)
```

### atan2 를 쓰는 이유

보통 `atan(y/x)` 를 쓰면 −90° ~ +90° 만 나온다. 그래서 2사분면과 4사분면을 구분하지 못한다.

`atan2(y, x)` 는 y 와 x 의 **부호를 따로 보기 때문에** −180° ~ +180° 전체를 정확히 구분한다.
또 x 가 0 일 때 나눗셈을 하지 않으므로 안전하다.

### 고도 식의 모양이 특이한 이유

교과서에는 보통 이렇게 나온다.

```
h = p / cos(위도) − N
```

이 식은 **위도가 90° 에 가까우면 cos 이 0 에 가까워져서 폭발한다.**
위도 89.9° 면 cos = 0.001745 이므로 오차가 573 배로 증폭된다.

그래서 나눗셈이 없는 형태로 바꿔 쓴다.

```
h = p · cos(위도) + Z · sin(위도) − a · √(1 − e² · sin²(위도))
```

수학적으로 같은 값이지만 **어느 위도에서도 안전하다.**

## 2-5. 공식 ③ : 회전 행렬 (DCM)

### 회전 행렬이란

좌표계 A 에서 잰 벡터를 좌표계 B 에서 잰 값으로 바꿔 주는 **3 × 3 숫자표** 다.
벡터에 이 표를 곱하기만 하면 변환된다.

```
V_B = R · V_A
```

좌표계를 바꿔도 **길이는 변하지 않는다.** (자를 바꿔도 물건 길이는 같다)
이런 성질을 가진 행렬을 **정규직교 행렬** 이라고 하고, 아주 유용한 성질이 하나 따라온다.

```
역변환 행렬 = 원래 행렬의 전치 (행과 열을 바꾼 것)
```

즉 역행렬을 따로 계산할 필요가 없다. 행과 열만 바꾸면 끝이다.

### (1) 동체 → NED 변환 행렬

자세각을 적용하는 순서는 **ZYX (yaw → pitch → roll)** 로 약속했다. 항공 분야 표준이다.

기호를 줄여서 c = cos, s = sin, φ = roll, θ = pitch, ψ = yaw 라고 하면

```
          | cψ·cθ    cψ·sθ·sφ − sψ·cφ    cψ·sθ·cφ + sψ·sφ |
R_b→n  =  | sψ·cθ    sψ·sθ·sφ + cψ·cφ    sψ·sθ·cφ − cψ·sφ |
          | −sθ      cθ·sφ               cθ·cφ            |
```

**검산해 보기** (이해에 큰 도움이 된다)

과제 표적은 roll = 0, pitch = 0 이다. 그러면 sφ = 0, cφ = 1, sθ = 0, cθ = 1 이므로

```
          | cos ψ   − sin ψ   0 |
R_b→n  =  | sin ψ     cos ψ   0 |
          |   0         0     1 |
```

여기에 `V_body = (V, 0, 0)` 을 곱하면

```
V_ned = ( V · cos ψ ,  V · sin ψ ,  0 )
      = ( 북쪽 성분  ,  동쪽 성분  ,  아래 성분 )
```

실제 값을 넣어 확인하면

| Yaw | cos ψ | sin ψ | V_ned (V = 200) | 해석 |
|---|---|---|---|---|
| 0° | 1 | 0 | (북 200, 동 0) | 북쪽 |
| 90° | 0 | 1 | (북 0, 동 200) | 동쪽 |
| 180° | −1 | 0 | (북 −200, 동 0) | 남쪽 ✔ 대공 표적 |
| 270° | 0 | −1 | (북 0, 동 −200) | 서쪽 ✔ 대함 표적 |

명세의 대함(Yaw 270° = 서), 대공(Yaw 180° = 남) 과 정확히 일치한다.

### (2) NED → ECEF 변환 행렬

이 행렬은 **표적이 지금 있는 위치의 위도·경도** 로 정해진다. 위치가 바뀌면 이 행렬도 바뀐다.

```
          | −sin(위도)·cos(경도)   −sin(경도)    −cos(위도)·cos(경도) |
R_n→e  =  | −sin(위도)·sin(경도)    cos(경도)    −cos(위도)·sin(경도) |
          |  cos(위도)              0           −sin(위도)           |
```

세 열이 각각 **북쪽 방향, 동쪽 방향, 아래 방향** 을 ECEF 로 표현한 것이다.

## 2-6. 공식 ④ : 속도 변환

위의 두 행렬을 이어 붙이면 속도를 한 번에 ECEF 로 옮길 수 있다.

```
1) V_body = ( V_heading , 0 , 0 )

2) V_ned  = R_b→n (자세각)      · V_body

3) V_ecef = R_n→e (현재 위도·경도) · V_ned
```

**중요** : 회전 행렬은 길이를 바꾸지 않으므로 세 단계를 거쳐도

```
| V_ecef |  =  V_heading
```

이 항상 성립한다. 이것이 나중에 계산이 맞는지 확인하는 가장 강력한 검증 수단이 된다.

## 2-7. 공식 ⑤ : 기동의 각속도

### 유도

반지름 R 인 원을 속도 V 로 돌 때, 바깥으로 쏠리는 가속도(구심가속도)는

```
a = V² / R
```

각속도 ω(오메가, 1초에 몇 라디안 도는가)는 `V = ω · R` 이므로 `R = V / ω` 이고, 이를 대입하면

```
a = V² / (V / ω) = V · ω
```

따라서

```
ω = a / V
```

여기서 가속도 a 는 명세가 준 Gravity Value 로 정해진다.

```
a = n · g          (n = Gravity Value,  g = 9.80665 m/s²)
```

**최종 식**

```
    ω = n · g / V          [rad/s]
```

단위를 확인해 보면 `(m/s²) ÷ (m/s) = 1/s` 로 각속도가 맞다.

### 함께 따라오는 두 식

```
선회 반경   R = V / ω = V² / (n · g)      [m]
선회 주기   T = 2π / ω = 2π · V / (n · g)  [s]
```

### 숫자 예 (대공 표적, V = 200 m/s, n = 1 G)

```
ω = 1 × 9.80665 / 200 = 0.049033 rad/s = 2.8094 °/s
R = 200² / 9.80665    = 4,078.9 m
T = 2π × 200 / 9.80665 = 128.14 s
60초 동안 도는 각도 = 2.8094 × 60 = 168.56°
```

한 바퀴 도는 데 128 초가 걸리므로, 60 초 시뮬레이션에서는 약 반 바퀴를 돈다.

### 이 식을 Roll 축에도 쓰는 것에 대하여 (한계)

`ω = n·g / V` 는 **원운동의 구심가속도** 에서 유도한 식이다.
Yaw(수평 선회)와 Pitch(수직 선회)에는 물리적으로 맞다.

그런데 Roll 은 몸을 옆으로 기울이는 것이라 구심가속도와 직접 관계가 없다.
그럼에도 같은 식을 쓴 이유는, **명세가 세 축 모두를 Gravity Value 하나로 지정하라고 했기 때문** 이다.
세 축에 같은 식을 쓰면 해석이 대칭적이고 설명이 일관된다.

**한계로 기록** : Roll 축 각속도는 물리적 유도가 아니라 명세를 대칭적으로 해석한 결과다.

## 2-8. 공식 ⑥ : 적분 — 조금씩 더해 나가기

### 적분이란

시간을 아주 잘게 쪼개서(여기서는 0.1 초), 그 짧은 동안의 변화를 계속 더해 나가는 것이다.

```
각도 변화 :  새 각도 = 이전 각도 + ω × Δt
위치 변화 :  새 위치 = 이전 위치 + V × Δt
```

`속도 × 시간 = 거리` 라는 중학교 공식 그대로다. 다만 이걸 600 번 반복한다. (기록은 t = 0 을 포함해 601 개가 남는다)

### 단순 방식(Euler)의 문제

가장 단순한 방법은 **스텝 시작 시점의 속도로 0.1 초 내내 간다** 고 보는 것이다.

직진이면 문제없다. 그런데 **도는 중이면 속도 방향이 계속 바뀐다.**
시작 방향으로만 0.1 초를 가면 원의 **접선 방향** 으로 나가므로 원 바깥으로 벗어난다.

**비유** : 운동장에서 원을 그리며 걷는데, 0.1 초마다 한 번씩만 방향을 고쳐 잡는다고 하자.
그 사이에는 직선으로 걷게 되므로 궤적이 원이 아니라 **다각형** 이 된다.

**오차 크기 계산**

한 스텝에 도는 각도를 Δ 라고 하면

```
Δ = ω × Δt = 0.049033 × 0.1 = 0.0049033 rad = 0.2809°
```

0.1 초 동안 기수는 Δ 만큼 돈다. 그 구간을 대표하는 방향은 한가운데인 `Δ/2` 지점의 방향인데,
Euler 는 시작 지점(0 지점)의 방향으로 간다. 즉 **매 스텝 방향이 `Δ/2` 만큼 뒤처진 채로** 움직인다.

자세각 자체는 `이전 각도 + ω × Δt` 로 정확히 적분되므로 이 뒤처짐이 눈덩이처럼 불어나지는 않는다.
대신 **궤적 전체가 진행 방향 옆으로 한 덩어리로 밀린다.** 밀리는 양은

```
밀림 = V × Δt / 2 = 200 × 0.1 / 2 = 10 m       (원의 중심이 10 m 옆으로 옮겨간다)
```

이고, 실제 위치와의 거리 오차는 반 바퀴 돌았을 때 최대가 되어 `V × Δt = 20 m` 에 이른다.
60 초(168.6° 선회) 시점에서 재 보면 **19.9 m** 다. 표적 추적에서 20 m 는 무시할 수 없는 값이다.

> 선회 **반경** 자체는 Euler 도 거의 정확하다. 0.1 초씩 끊어 가는 데서 오는 반경 오차는 두 방식 모두 +0.004 m 로 같다.
> 이 방식의 결함은 반경이 아니라 **궤적이 통째로 반 스텝만큼 밀리는 것** 이다.

### 채택한 방식 : 중점법 (Midpoint, RK2)

**스텝의 시작 방향이 아니라 가운데 시점의 방향으로 간다** 고 보는 방법이다.

"가운데 시점의 방향" 을 만들려면 가운데 시점의 값이 **두 가지** 필요하다.
속도는 `R_n→e (위도·경도) · R_b→n (자세각)` 으로 만들기 때문이다.

- 가운데 시점의 **자세각** → 기수가 그 사이에 돈 만큼을 반영한다
- 가운데 시점의 **위치(위도·경도)** → 그 사이에 움직여서 "북쪽·아래" 방향이 달라진 만큼을 반영한다

```
1) 각속도 ω 계산

2) 가운데 시점 자세각
   att_mid = att + ω × (Δt / 2)

3) 가운데 시점 위치 : 지금 속도로 반 스텝만 가 본다
   V_0   = R_n→e (현재 위도·경도) · R_b→n (att) · (V_heading, 0, 0)
   P_mid = P_ecef + V_0 × (Δt / 2)
   P_mid 를 위도·경도로 변환 (공식 ②)

4) 가운데 자세각과 가운데 위치로 속도 계산
   V_mid = R_n→e (P_mid 의 위도·경도) · R_b→n (att_mid) · (V_heading, 0, 0)

5) 위치 갱신 : 원래 위치에서 V_mid 로 한 스텝 전체를 간다
   P_ecef = P_ecef + V_mid × Δt

6) 새 위치를 위도·경도·고도로 변환 (공식 ②)

7) 자세각을 att + ω × Δt 로 갱신하고 −180° ~ +180° 로 정규화

8) 새 위도·경도와 새 자세각으로 최종 속도를 다시 계산해 저장

9) simTime = simTime + Δt
```

3) 의 P_mid 는 **방향을 정하는 데만 쓰고 버린다.** 실제 이동은 5) 에서 원래 위치를 기준으로 한다.

**정확도 비교** (200 m/s, 1 G 선회, 60 초 뒤 위치 오차. 기준은 Δt = 0.001 초로 돌린 결과)

| Δt | Euler | 중점법 (RK2) |
|---|---|---|
| 0.1 초 | 19.91 m | 0.0081 m |
| 0.05 초 | 9.95 m (1/2) | 0.0020 m (1/4) |
| 0.025 초 | 4.98 m (1/2) | 0.0005 m (1/4) |

간격을 절반으로 줄였을 때 Euler 는 오차가 절반이 되고(Δt 에 비례), 중점법은 4 분의 1 이 된다(Δt² 에 비례).
같은 0.1 초 간격에서 오차가 약 2,500 분의 1 이다.

계산량은 Euler 보다 스텝마다 속도 만들기 2 번, 위도·경도 변환 1 번이 더 든다.
그래도 최악 조건(표적 10 개 × 기동 30 개, 100,000 스텝)을 전부 도는 데 0.73 초라 부담이 되지 않는다.
같은 정확도를 Euler 로 내려면 간격을 2,500 배 잘게 쪼개야 하므로 중점법 쪽이 훨씬 싸다.

## 2-9. 전체 알고리즘 정리

### 초기화 (t = 0)

```
1) P_ecef ← LLA → ECEF 변환                      (공식 ①)
2) 자세각 ← 초기 자세각 그대로
3) V_body = (V_heading, 0, 0)
4) V_ned  = R_b→n · V_body                       (공식 ③-(1))
5) V_ecef = R_n→e · V_ned                        (공식 ③-(2))
6) simTime = 0
```

### 매 스텝 (0.1 초마다, 총 600 회)

```
1) 현재 시각 t 에 해당하는 기동 찾기
     startTime ≤ t < endTime 인 기동
     (구간이 겹치지 않도록 검증했으므로 최대 1 개)

2) 각속도 ω = n · g / V_heading                   (공식 ⑤)
     기동이 없으면 ω = 0
     TurnType 에 따라 roll / pitch / yaw 중 하나에만 적용

3) 이후는 2-8 중점법 절차의 2) ~ 9) 와 같다
```

### 입력 검증 (시뮬레이션 시작 전 1 회)

- NULL 포인터
- 표적 개수 1 ~ 10, 기동 개수 0 ~ 30
- Δt > 0, 전체 시간 ≥ Δt
- **V_heading > 0** ← 각속도 식의 분모이므로 반드시 확인
- TurnType 이 정의된 4 개 값 중 하나인가
- 0 ≤ startTime < endTime ≤ 전체 시간
- **같은 표적의 기동 구간이 겹치지 않는가**

## 2-10. 검증 계획과 예상값, 그리고 실측값

계산이 맞는지 확인하는 방법을 미리 정해 두었다.
각 항목의 **예상** 은 이론으로 계산한 값이고, **실측** 은 구현한 Core 를 과제 조건(60 초 / 0.1 초)으로 돌려 잰 값이다.
(실측 : 2026-09-17, x64 Debug 와 Release 의 결과가 서로 같다)

### (1) 속도 크기 보존 — 가장 강력한 검증

회전 행렬은 길이를 바꾸지 않으므로, 모든 스텝에서

```
| V_ecef | = V_heading
```

이 성립해야 한다. 어긋나면 행렬이 잘못된 것이다. 목표 오차 : 1 × 10⁻⁹ m/s 이내

```
실측 : 600 스텝 전체에서 차이의 최댓값   대함 3.6 × 10⁻¹⁵ m/s,  대공 2.8 × 10⁻¹⁴ m/s
```

### (2) 경로 길이

등속이므로 총 이동 거리는

```
거리 = V × t
```

- 대함 표적 : 30 × 60 = **1,800 m**
- 대공 표적 : 200 × 60 = **12,000 m**

```
실측 : 스텝마다 움직인 거리를 모두 더한 값과의 차이   대함 −4.7 × 10⁻⁹ m,  대공 −2.5 × 10⁻⁹ m
```

### (3) 대함 표적 (서쪽으로 1,800 m)

경도 1 도에 해당하는 거리는 위도에 따라 달라진다.

```
경도 1도 거리 = (π/180) × N × cos(위도)
```

위도 32.125° 에서 N = 6,384,183 m 이므로

```
경도 1도 = 0.0174533 × 6,384,183 × cos(32.125°) = 94,365 m
Δ경도   = −1,800 / 94,365 = −0.019075°
```

```
예상 : 60초 후 경도 = 126.03 − 0.019075 = 126.010925°
       위도는 32.125° 유지 (변화 < 0.00001°)
```

```
실측 : 60초 후 경도 126.010925075°,  위도 32.125000000° (60 초 동안 변한 폭 3 × 10⁻¹⁴°),  고도 0.0000 m
```

### (4) 대공 표적 (남쪽으로 12,000 m)

위도 1 도에 해당하는 거리는 다른 반지름(자오선 곡률 반지름 M)을 쓴다.
표적이 지표면이 아니라 **고도 h = 300 m 위를 날기 때문에** 반지름에 h 를 더해야 한다.

```
M = a(1 − e²) / (1 − e² sin²(위도))^1.5
위도 1도 거리 = (π/180) × (M + h)
```

위도 32.12° 에서 M = 6,353,467 m 이므로

```
위도 1도 = 0.0174533 × (6,353,467 + 300) = 110,894 m
Δ위도   = −12,000 / 110,894 = −0.108211°
```

```
예상 : 60초 후 위도 = 32.12 − 0.108211 = 32.011789°
       (남쪽으로 가는 동안 M 이 조금씩 변하는 것까지 넣어 잘게 나눠 더하면 32.011788°)
       경도는 126.0° 유지 (변화 < 0.00001°)
       고도는 300 m 유지
```

**h 를 빼먹으면** `−12,000 / 110,889 = −0.108216°` → 32.011784° 가 되어 약 0.57 m 어긋난다.
같은 각도를 돌아도 300 m 위에서는 그만큼 더 긴 길을 가야 하기 때문이다(12,000 m × 300 / 6,353,467 = 0.57 m).
같은 이유로, 출발점과 도착점의 위도·경도로 **지표면 위 거리** 를 재면 12,000 m 가 아니라 11,999.43 m 가 나온다.

**고도가 유지되는 이유** : 속도가 항상 그 지점의 수평면 안에 있으므로(pitch = 0),
지구 곡률을 따라 돌면서 높이는 변하지 않는다.

```
실측 : 60초 후 위도 32.011787774°,  경도 126.000000000° (변한 폭 8 × 10⁻¹⁴°),  고도 300.000000 m
```

### (5) 선회 시험

대공 표적에 `TurnType = Yaw`, `Gravity Value = 1.0`, 0 ~ 60 초 기동을 건다.

```
예상 선회 반경 R = 4,078.9 m
예상 선회 주기 T = 128.14 s
60초 회전각      = 168.56°
```

궤적을 NED 로 변환해 중심으로부터의 거리가 4,078.9 m 와 1 % 이내로 일치하는지 확인한다.

```
실측 : 601 개 점에 원을 맞춘 반경 4,077.47 m (예상보다 1.39 m, 0.034 % 작다),  60초 회전각 168.5639°,  고도 300.000000 m
```

**1.39 m 는 계산 오차가 아니다.** 같은 선회를 적도에서 돌리면 4,078.868 m 로 예상과 4 mm 차이로 맞고,
위도 60° 에서는 3.84 m 작게 나온다. 위도가 높을수록 커지는 차이다.

이유는 Yaw 를 **그 지점의 북쪽** 을 기준으로 재기 때문이다. 북반구에서는 경도선들이 북극 쪽으로 모이므로,
표적이 동서로 움직이면 "그 지점의 북쪽" 자체가 조금씩 돌아간다(자오선 수렴).
남쪽을 보고 출발해 도는 이번 선회에서는 그 돌아가는 방향이 선회 방향과 같아서, 멀리서 보면 선회가 조금 더 급해진다.
(북쪽을 보고 출발해 돌면 반대로 반경이 조금 커진다)

### (6) 적분 방식 비교

같은 선회 시나리오를 Euler 로도 계산해 중점법과 비교한다.

```
예상 : Euler 는 궤적이 옆으로 밀려 위치 오차 최대 20 m (60초 시점 19.9 m), 중점법은 0.008 m
```

```
실측 : 60초 시점 위치 오차   Euler 19.91 m,  중점법 0.0081 m    (기준 : Δt = 0.001 초로 돌린 결과)
       Δt 를 0.1 → 0.05 → 0.025 초로 줄이면   Euler 는 19.91 → 9.95 → 4.98 m (매번 1/2)
                                             중점법은 0.0081 → 0.0020 → 0.0005 m (매번 1/4)
```

### (7) 오류 처리

NULL 인자, 표적 개수 0 또는 11, 기동 개수 31, Δt = 0, V_heading = 0,
기동 구간 겹침, 정의되지 않은 TurnType — 각각 올바른 상태코드를 반환하는지 확인

```
실측 : 차례대로 TGT_ERR_NULL / TGT_ERR_TARGET_NUM / TGT_ERR_MANEUVER_NUM / TGT_ERR_TIME / TGT_ERR_SPEED /
       TGT_ERR_MANEUVER_OVERLAP / TGT_ERR_TURN_TYPE.  끝과 시작이 맞닿은 기동([10,20) 과 [20,25))은 TGT_OK
```

## 2-11. 알려진 한계

### (1) 짐벌락 (Gimbal Lock)

자세를 Roll·Pitch·Yaw 세 각도로 표현하는 방식의 고질적인 문제다.

**Pitch 가 ±90° (수직 상승/하강) 가 되면 Roll 과 Yaw 를 구분할 수 없게 된다.**

**비유** : 지구본에서 북극점에 서 있으면 "동쪽" 이 어느 방향인지 정의할 수 없다.
어느 쪽으로 가도 남쪽이기 때문이다.

이번 과제의 시나리오는 Pitch 를 0 으로 유지하므로 문제가 생기지 않는다.
수직 기동까지 다루려면 사원수(Quaternion) 로 바꿔야 한다.

### (2) Roll 축 각속도의 물리적 근거

2-7 에서 설명한 대로, `ω = n·g/V` 를 Roll 에 적용하는 것은 물리적 유도가 아니라
명세를 대칭적으로 해석한 결과다.

### (3) NED 기준 위치 — 처음 구현의 결함과 정정 (2026-09-17)

처음에는 매 스텝의 NED → ECEF 행렬을 **스텝 시작 위치** 의 위도·경도로 만들었다.
0.1 초에 20 m 움직이는 동안 NED 축이 돌아가는 양이 `20 / 6,378,000 = 3 × 10⁻⁶ rad`
(약 0.0002°) 뿐이라 무시해도 된다고 봤기 때문이다.

**무시하면 안 됐다.** 한 스텝의 양은 작지만 매 스텝 같은 쪽으로만 쌓인다.

- 수평 비행은 "그 지점의 수평 방향으로 직진" 이다. 지구는 둥근데 0.1 초 동안 직선으로 가면
  도착한 곳에서는 고도가 `d² / 2R = 20² / (2 × 6,353,767) = 0.00003 m` 만큼 높아져 있다.
  600 스텝이면 **1.9 cm** 다. 실제로 대공 표적의 60 초 뒤 고도가 300.0189 m 로 나왔다.
- 선회 끝 위치 오차가 0.0081 m 가 아니라 **0.021 m** 였다 (위아래로 1.9 cm, 수평으로 1.1 cm).
- Δt 를 절반으로 줄여도 오차가 1/4 이 아니라 **1/2 로만** 줄었다. 자세각만 가운데 값을 쓰고
  위치는 시작 값을 썼으므로, 위치 쪽은 여전히 Euler 와 같은 1 차 정확도였던 것이다.

그래서 2-8 의 3) 단계를 넣었다. 반 스텝만 가 본 위치의 위도·경도로 행렬을 만들면
가운데 시점의 "수평 방향" 으로 가게 된다. 그 방향은 출발점의 수평보다 아주 조금(`d / 2R`) 아래를 향한다.
그래서 스텝 앞쪽 절반에서 내려간 만큼(한가운데에서 0.008 mm) 뒤쪽 절반에서 다시 올라와, 도착점에서 고도가 제자리로 돌아온다.
둥근 지구 위의 두 점을 직선으로 이으면 그 직선이 가운데에서 땅 쪽으로 살짝 파고드는 것과 같다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 대공 표적 60 초 뒤 고도 | 300.0189 m | 300.000000 m |
| 대함 표적 60 초 뒤 위도 | 32.124999998° | 32.125000000° |
| 1 G 선회 끝 위치 오차 (Δt 0.1 초) | 0.021 m | 0.0081 m |
| Δt 를 절반으로 줄였을 때 오차 | 약 1/2 | 1/4 |

**배운 점** : "중점법" 은 상태 전체(자세와 위치 둘 다)를 가운데 값으로 써야 중점법이다.
하나라도 시작 값을 쓰면 그 부분의 1 차 오차가 전체 오차를 정한다.
