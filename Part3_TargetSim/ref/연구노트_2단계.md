## 목적

1. 과제 명세 1-(2): 표적 상태(위치·속도)를 ECEF 에서 갱신하는 엔진을 구현한다.
2. 동체 속도 V_heading 을 ECEF 성분(Vx, Vy, Vz)으로 바꾸는 방법을 정한다.

## 방법

- 함수: `f_Tgt_ValidateConfig`(입력 검증), `f_Tgt_InitState`(초기 상태), `f_Tgt_StepTarget`(1스텝 전파), `f_Tgt_StatusStr`
- 속도 변환
  - V_b = [V, 0, 0]ᵀ
  - V_n = C_b→n(자세) · V_b = V · [cosψ·cosθ, sinψ·cosθ, −sinθ]ᵀ (roll 과 무관)
  - V_e = C_n→e(위도 φ, 경도 λ) · V_n
- 기동: ω = n·g / V (구심가속도 V·ω = n·g) 를 TurnType 축의 오일러각 변화율로 적용한다.
- 적분: 중점법 (자세만 스텝 중앙값, C_n→e 는 스텝 시작 위경도)
  - att_mid = att_k + ω·Δt/2, att_k+1 = wrap(att_k + ω·Δt)
  - P_k+1 = P_k + C_n→e(φ_k, λ_k) · C_b→n(att_mid) · V_b · Δt
  - (φ, λ, h)_k+1 = Bowring(P_k+1)
  - V_e,k+1 = C_n→e(φ_k+1, λ_k+1) · C_b→n(att_k+1) · V_b, t_k+1 = t_k + Δt
- 기동 판정: startTime ≤ t + ε < endTime, ε = 1e-6 s (0.1 s 누적 반올림 오차 대비)
- 입력 검증 순서: NULL → 표적 수 → 시간 → 표적별(기동 수 → 속도 → 기동별 TurnType·시간 → 겹침). 기동 구간은 [start, end) 라 맞닿으면 겹침이 아니다.
- 모든 변환이 성공했을 때만 상태를 반영한다 (실패하면 상태 불변).
- 검증: 솔루션 밖 임시 하네스로 명세 조건(60 s / 0.1 s), 1 G 선회, Δt 0.001 s 기준해 대비 Euler 비교, 오류 코드 판정표를 확인했다.

## 결과

- 속도 크기 오차(‖V_ecef‖ 와 V 의 최대 차, 대함·대공 직진·1 G 선회 601 표본) ≤ 5.7e-14 m/s (선회에서 최대, 직진 ≤ 2.9e-14)
- 경로 길이 오차(스텝 이동 거리 합과 V·60 의 차) ≤ 6.4e-9 m (대함 1,800 m 에서 최대, 대공 12,000 m 는 5.4e-10 m)
- 대함 60 s: 경도 126.0300° → **126.0109251°** (위도권 해석해와 9e-13° 차), 위도 변화 2.4e-9°
- 대공 60 s: 위도 32.1200° → **32.0117878°** (고도 300 m 자오선 해석해와 1.6e-10° 차, 고도 상승 1.9 cm 영향), 경도 변화 0, 고도 300.0189 m
- 1 G Yaw 선회 (대공 표적 초기값 32.12°·126.0°·300 m·yaw 180°·200 m/s, 0~60 s Yaw +1 G)
  - 이론 반경 4,078.86 m, 주기 128.14 s
  - 원 맞춤 반경 **4,077.47 m** (−0.034 %)
  - 60 s yaw 변화 168.5639° (이론과 6e-14 rad 차, 국지 북 기준 자세각).
    시작점 NED 에서 잰 속도 방향 변화는 168.609° (자오선 수렴분 +0.045°)
- 1 G Yaw 선회 시나리오의 60 s 끝 위치 오차 (중점법 Δt 0.001 s 기준해 대비. 직진이면 두 방식 결과가 같다)

  | 방식 | Δt 0.1 s | Δt 0.01 s | Δt 0.001 s |
  |---|---|---|---|
  | Euler | 19.91 m | 1.99 m | 0.20 m |
  | 중점법 | **0.021 m** | 0.0018 m | (기준) |

  - Δt 0.1 s 에서 Euler 오차가 중점법의 약 930 배다. Euler 오차는 Δt 에 1차로 비례한다.
  - 중점법 오차도 Δt 0.1 → 0.01 s 에서 약 12 배만 줄어 사실상 1차다. 스텝 시작 위경도를 기준으로 생기는 고도 상승이 Δt 에 비례하기 때문이다 (Δt 0.1 s 오차 0.021 m 중 고도 성분 0.019 m).
- 0.1 을 k번(k = 1~600) 누적한 값을 경계값 k/10 (입력 리터럴 10.0 등과 같은 값)과 비교하면 146개에서 누적 시각이 경계값보다 작다 (모자라는 쪽 최대 4.3e-14 s, 넘치는 쪽까지 합친 최대 편차는 k = 600 의 5.8e-13 s).
  - ε 이 없으면 이런 경계에서 기동 시작이나 종료가 한 스텝 늦어진다.
  - 10~20 s 기동이면 10 s 경계만 해당해(누적값 9.99999999999998) 102~200번째 스텝, 99 스텝만 작동한다.
  - ε 을 적용하면 정확히 101~200번째 스텝(100 스텝)에서만 작동했다.
- Roll 기동은 궤적이 직진과 같고(차이 0 m) roll 각만 바뀐다. Pitch(+) 기동에서 고도 상승을 확인했다.
- 오류 처리 37건을 포함한 점검 65건 통과. x64 Debug / Release 경고 0, MSVC /analyze 와 clang-tidy 경고 0.

## 한계

- Roll 에 ω = n·g/V 를 쓰는 것은 물리적 근거 없는 대칭 해석이다. 롤 속도가 속도에 반비례한다
  (1 G 기준 200 m/s 에서 2.8°/s, 30 m/s 에서 18.7°/s).
- 오일러각을 직접 적분한다.
  - pitch ±90° 에서 짐벌락이 생겨 yaw 기동이 궤적을 바꾸지 못한다.
  - pitch ≠ 0 이면 yaw 기동의 구심가속도가 n·g·cosθ 로 줄어든다.
  - roll ≠ 0 인 상태의 pitch 기동은 기울어진 평면이 아니라 연직면에서 돈다.
- NED 기준을 스텝 시작 위경도로 잡아 스텝마다 고도가 (V·Δt)² / 2R 씩 오른다 (대공 60 s 에 +1.9 cm).
  중점법에 남은 오차의 대부분이 이것이고, 이 때문에 전체 수렴 차수가 1차다.
- yaw 가 국지 북 기준이라, 동서로 움직이면 자오선 수렴만큼 국지 북이 돌아 실제 선회율이 달라진다.
  - 북반구에서 서쪽으로 가며 우선회(또는 동쪽으로 가며 좌선회)하면 반경이 준다 (대공 초기값 yaw 180°, +1 G: −1.39 m).
  - 동쪽으로 가며 우선회하면 반경이 는다 (yaw 0°, +1 G: +1.40 m). 적도에서는 차이가 없다 (+0.003 m).
- 기동 시작·종료는 스텝 단위로 양자화되고, ε(1 µs) 만큼 경계가 앞당겨진다.
- 입력 검증(`f_Tgt_ValidateConfig`)의 범위
  - 2단계에서는 플랫폼 설정을 보지 않았다(속도 음수도 통과). → 3단계에서 플랫폼 속도 검사 추가
  - 표적·플랫폼 모두 위경도·자세·Gravity Value 의 범위와 NaN 을 검사하지 않는다 (2단계에서는 표적 속도·durationTime·stepTime 이 NaN 이어도 `TGT_OK`). → 3단계에서 durationTime·stepTime 의 NaN·Inf 는 `TGT_ERR_TIME` 으로 거부, 표적 속도 NaN 은 지금도 `TGT_OK`
- 정지 플랫폼(0 m/s)은 `f_Tgt_StepTarget` 으로 전파할 수 없다 (속도 ≤ 0 거부). → 3단계 실행기의 플랫폼 전용 경로로 해결
- 자세각 wrap 범위는 `f_Coord_WrapAngle` 특성상 [−π, π] 다.
- gcc 교차 확인은 설치 환경이 없어 하지 못했고 clang 프런트엔드(clang-tidy)로 대신했다.
