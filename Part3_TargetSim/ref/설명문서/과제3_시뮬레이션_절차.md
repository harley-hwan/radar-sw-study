# 과제 3 — 「2. 시뮬레이션 조건」 시간·절차순 수행 설명

명세가 준 조건값이 **어느 시점에 어떤 함수로 소비되어 어떤 결과가 되는지**를 실행 순서대로 정리한다.

## 절차 1 — 설정 구성 (UI → `ST_SimConfig`)

**시점** : 실행 직전 (표의 값을 고칠 때마다 자동 실행). UI 의 편집 모델 `CScenario::f_BuildConfig` 가 표의 글자를 읽어 구조체를 채운다.

1. `f_Num_Parse()` 로 각 편집 칸을 `FLOAT64` 로 파싱. 빈 칸·구문 오류·범위 초과는 어느 칸인지 지목해 반려한다.
2. **각도 단위 변환** — 위도·경도·자세각은 여기서만 deg → rad (`f_Deg_To_Rad`). 이 지점을 지나면 Core 어디에도 deg 는 없다.
3. 명세값이 들어가는 자리

```
durationTime = 60.0                       stepTime = 0.1
st_Platform  : lat = rad(32.0),  lon = rad(126.0),  alt = 0,   V = 0,   roll/pitch/yaw = 0
st_Target[0] : lat = rad(32.125), lon = rad(126.03), alt = 0,   V = 30,  yaw = rad(270)
st_Target[1] : lat = rad(32.12),  lon = rad(126.0),  alt = 300, V = 200, yaw = rad(180)
nTargetNum   = 2
```

4. **UI 단계 선검증** (Core 가 판정할 수 없거나, 판정해도 어느 칸인지 알려줄 수 없는 것들)

| 검사 | 기준 | 이유 |
|---|---|---|
| 갱신 간격 해상도 | 1 ms (0.001 s) 단위 | 그 이하는 표현·표시 모두 의미가 없다 |
| 기동 시각 격자 | `stepTime` 의 정수배 | 격자 밖 시각은 다음 스텝으로 밀리거나 기동이 통째로 무시된다 |
| 스텝당 회전각 | `(\|G\|·g / V)·Δt ≤ 30°` | 중점법 오차 급증 및 비물리 선회 차단. 허용 \|G\| 상한을 내림해서 함께 표시 |
| 값의 유한성 | `isfinite` | NaN/Inf 가 Core 로 들어가지 않게 한다 |

## 절차 2 — 설정 검증 (`f_Tgt_ValidateConfig`)

**시점** : `f_Tgt_InitSim` 진입 직후, 그리고 **매 스텝마다 다시**.

검사 순서 (먼저 걸린 것이 반환된다)

```
1. st_Config == NULL                                              -> TGT_ERR_NULL
2. nTargetNum 이 1..10 밖                                          -> TGT_ERR_TARGET_NUM
3. f_Tgt_GetStepNum() < 1                                          -> TGT_ERR_TIME
4. 플랫폼 속력이 [0, inf) 가 아님 (긍정형 비교 → NaN 도 여기서 탈락)  -> TGT_ERR_SPEED
5. 표적별 : nManeuverNum 0..30, headingSpeed > 0                    -> TGT_ERR_MANEUVER_NUM / TGT_ERR_SPEED
6. 표적별 기동 : TurnType 0..3                                      -> TGT_ERR_TURN_TYPE
              0 ≤ start < end ≤ durationTime                       -> TGT_ERR_TIME
              같은 표적 내 구간 겹침                                 -> TGT_ERR_MANEUVER_OVERLAP
```

### 스텝 수 산출 — `f_Tgt_GetStepNum()`

```c
if ((stepTime >= TGT_MIN_STEP_TIME) && (durationTime >= stepTime)) {   // 긍정형 → NaN 탈락
    ratio   = durationTime / stepTime;          // 60.0 / 0.1 = 600.0,  0.3 / 0.1 = 2.9999999999999996
    nearest = floor(ratio + 0.5);               // 600.0,              3.0
    if ((nearest <= TGT_MAX_STEP_NUM) && (fabs(ratio - nearest) <= 1e-6)) {
        nStepNum = (INT32)nearest;              // 범위 확인 후에만 정수 변환
    }
}
```

- **정수배 강제** : `durationTime` 이 `stepTime` 의 정수배가 아니면 거부한다. 마지막 스텝만 길이가 다른 상황을 만들지 않기 위해서다. 60.0 / 0.1 은 정확히 600.0 이 나오지만, 0.3 / 0.1 = 2.9999999999999996 처럼 정수배인데도 몫이 정수가 아닌 경우가 있어 1e-6 허용오차로 판정한다.
- **정수 변환 전 범위 확인** : 범위 밖 또는 NaN 인 실수를 정수로 변환하는 것은 C 표준상 미정의 동작이다.

**명세 조건 적용 결과 : `nStepNum = 600`, 표본 수 = 601 (t = 0.0 … 60.0)**

## 절차 3 — 초기화 (`f_Tgt_InitSim`), t = 0

객체마다 `f_Tgt_InitState()` 를 호출한다. 내부 순서는 다음과 같다.

```
1. simTime = 0
2. st_Lla  = 설정값 그대로
3. st_Att  = f_Coord_WrapAngle(설정 자세)                  // Yaw 270° → -90° 로 정규화
4. st_PosEcef = f_Trans_Lla_To_Ecef(st_Lla)                // N = a / sqrt(1 - e² sin²φ)
5. st_VelEcef = f_Tgt_GetVelEcef(st_Att, st_Lla, V)        // body → NED → ECEF
6. 다섯 항목 모두 성공했을 때만 한 번에 *st_State 로 복사   // 중간 실패 시 원상 유지
```

### 명세 시나리오 t=0 실제값

| 객체 | ECEF 위치 [m] | ECEF 속도 [m/s] | \|V\| |
|---|---|---|---|
| 플랫폼 | (−3 182 303.576, 4 380 065.108, 3 360 431.434) | (0, 0, 0) | 0 |
| 대함 | (−3 180 268.484, 4 372 447.759, 3 372 178.197) | (24.2613, 17.6463, 0.0000) | 30.000000 |
| 대공 | (−3 178 301.273, 4 374 556.410, 3 371 868.139) | (−62.5044, 86.0299, −169.3873) | 200.000000 |

대공 표적의 `V_z` 가 음수인 것은 남향 비행이 ECEF z축(북극 방향) 성분을 줄이기 때문이다. 고도가 내려가는 것이 아니다.

### 초기화 마무리

```
st_Sample.nStepIndex = 0,  simTime = 0,  nTargetNum = 2
st_Target[2] ~ st_Target[9] : f_Tgt_ClearState() 로 0 충전   // 표·CSV·그림이 쓰레기를 읽지 않도록
st_Sim->st_Config = *st_Config                               // 설정 사본 보관
st_Sim->nStepNum  = 600
```

설정을 **사본으로** 들고 가므로, 실행 중 사용자가 UI 편집 칸을 바꿔도 진행 중인 시뮬레이션은 흔들리지 않는다.

## 절차 4 — 메인 루프, k = 1 … 600

UI 가 `601 × sizeof(ST_SimSample)` = **680.8 KB** 를 `calloc` 으로 한 번에 잡고, 표본 0 을 넣은 뒤 600회 반복한다.

### 한 스텝 안의 순서 (`f_Tgt_StepSim`)

```
① 재검증          f_Tgt_ValidateConfig()  +  nStepNum·nStepIndex·nTargetNum 정합성
                  ST_SimState 는 공개 구조체라 호출 사이에 외부에서 망가질 수 있다 (MISRA Dir 4.1 / Rule 18.1)
② 종료 판정       nStepIndex == nStepNum 이면 TGT_ERR_SIM_END
③ 시각 산출       curTime  = nStepIndex     * stepTime        ← 누적이 아니라 곱셈
                  nextTime = (nStepIndex+1) * stepTime
④ 표본 사본       st_Next = st_Sim->st_Sample                 ← 원본은 아직 건드리지 않는다
⑤ 플랫폼 진행     f_Tgt_StepPlatformAt()  — 각속도 (0,0,0) 고정
⑥ 표적 진행       nTarget = 0 .. nTargetNum-1  각각 f_Tgt_StepTargetAt()
⑦ 커밋            전원 TGT_OK 일 때만  nStepIndex++, simTime = nextTime, 원본에 반영
```

**③ 시각을 곱셈으로 만드는 이유** — 0.1 은 이진 부동소수로 정확히 표현되지 않는다(0.10000000000000000555…). 600번 누적하면 60.00000000000058 (오차 5.8e-13), 곱하면 정확히 60.0. 기동 구간 판정이 이 시각을 쓰므로 누적 오차는 곧 기동 시점 오차가 된다.

**④⑦ 사본 후 일괄 커밋** — 표적 1은 진행하고 표적 2에서 실패하면, 한 표본 안에 서로 다른 시각의 상태가 섞인다. 사본에서 전부 끝낸 뒤 한 번에 옮기면 그런 중간 상태가 외부에 노출되지 않는다.

### 표적 한 개를 한 스텝 진행하는 내부 순서

```
1. 기동 조회      evalTime = curTime + 1e-6 로 [start, end) 를 만족하는 첫 기동
2. 각속도         ω = (G · 9.80665) / V   → TurnType 에 따라 roll / yaw / pitch 축에 대입
3. 중점 자세      att_mid = att + rate · (Δt/2)
4. 시작 속도      V_k     = C(ned→ecef)(LLA_k) · C(body→ned)(att_k) · (V,0,0)
5. 중점 위치      P_mid   = P_k + V_k · (Δt/2),   LLA_mid = f_Trans_Ecef_To_Lla(P_mid)
6. 중점 속도      V_mid   = C(ned→ecef)(LLA_mid) · C(body→ned)(att_mid) · (V,0,0)
7. 위치 갱신      P_{k+1} = P_k + V_mid · Δt
8. 좌표 환산      LLA_{k+1} = f_Trans_Ecef_To_Lla(P_{k+1})       ← Bowring 폐형식
9. 종단 자세      att_{k+1} = wrap(att + rate · Δt)
10. 보고 속도     V_{k+1} = C(ned→ecef)(LLA_{k+1}) · C(body→ned)(att_{k+1}) · (V,0,0)
```

6단계에서 쓰는 NED 기준 위경도는 **반 스텝 뒤 위치(LLA_mid)** 다. 스텝 시작 위경도(LLA_k)를 그대로 쓰면 그 사이 지구 곡률만큼 방향이 뒤처져, 수평 비행인데도 고도가 스텝마다 `d²/2R` 씩 오르고(대공 표적 60초에 1.9 cm) 위치 오차가 Δt 에 비례해서만 줄어든다. P_mid 는 방향을 정하는 데만 쓰고, 7단계의 이동은 P_k 에서 출발한다.

10단계의 속도는 다음 스텝 계산에 쓰이지 않고 출력·검증용이다(다음 스텝이 4단계에서 자세와 위치로부터 다시 만든다).

플랫폼은 V = 0, 각속도 0 이므로 같은 경로를 타고도 60초 내내 제자리다. 표적과 경로를 공유하는 이유는 코드 중복 제거이며, 이 경로에는 속도로 나누는 연산이 없어 V = 0 이 안전하다(각속도 계산은 기동이 있는 표적 경로에만 있다).

## 절차 5 — 결과 출력

### (a) LLA 표 / CSV — 명세 "LLA 좌표 값으로 출력"

601행 × (2 + 3×3)열. 열 순서는 `스텝 | 시각 | 플랫폼 위/경/고 | 표적1 위/경/고 | 표적2 위/경/고` 로 표와 CSV 가 동일하다.

- 표는 **가상 리스트**(`LVS_OWNERDATA`) 로 그린다. 601행이면 실항목으로 넣어도 되지만, 스텝 간격을 1 ms 로 낮추면 최대 100,001행이 되므로 처음부터 필요한 행만 그리게 한다.
- 위경도 9자리, 고도 4자리. 위도 1e-9° ≈ 0.1 mm 이므로 이 자릿수 아래로는 의미가 없다.
- CSV 는 절대 경로만 허용하고, 쓰기 실패 시 반쯤 쓴 파일을 `_wremove` 로 지운다.

### (b) 궤적 그림 — 명세 "위치 정보를 그림으로 표현"

ECEF 좌표를 그대로 그리면 축 값이 3.2e6 수준이고 지구 중심 기준이라 궤적이 보이지 않는다. **표본 0 의 플랫폼 위치를 원점으로 하는 국소 NED 평면**으로 옮겨 East–North 2D 로 그린다.

```
기준 DCM  C(ned→ecef)(플랫폼 초기 위경도)   ← 전체에서 단 한 번만 생성
각 점     ΔP     = P_ecef - P_ecef(플랫폼, t=0)
          P_ned  = C(ned→ecef)ᵀ · ΔP        ← 정규직교이므로 전치가 역변환
          (east, north) = (P_ned.y, P_ned.x)
```

`f_Trans_Ecef_To_Ned()` 를 점마다 부르면 601×3 = 1,803회 DCM 을 새로 만든다. 기준점이 고정이므로 한 번만 만들어 재사용한다.

변환 전에 `f_Ui_IsStateFinite()` 로 NaN/Inf 를 한 번 더 거른다. 그림·표·CSV 에 비유한 값이 나가지 않게 하는 마지막 방어선이다.

### (c) 버퍼 교체 규칙

새 버퍼를 따로 잡아 601 표본을 모두 채우고, 그림 좌표까지 전부 성공한 뒤에만 기존 버퍼와 교체한다. 중간 실패 시 이전 실행 결과가 그대로 남는다(부분 결과를 보여주지 않는다).

## 절차 6 — 검증

### 예상값 (기동 없음, 60초)

| 검증 항목 | 이론값 | 근거 |
|---|---|---|
| \|V\| 보존 (전 구간, 두 표적) | 30.000000 / 200.000000 m/s | 정규직교 회전만 거치므로 노름 불변 |
| 대함 이동거리 | 30 × 60 = **1 800 m** | 등속 직진 |
| 대함 최종 위치 | 위도 **32.125000°** 유지, 경도 **126.010925°** | Yaw 270° = 항상 정서 → 평행권 추종. 평행권 반경 r = (N+h)cos φ = 5 406 700 m, Δλ = −1800/r = −0.0190749° |
| 대공 이동거리 | 200 × 60 = **12 000 m** | 등속 직진 |
| 대공 최종 위치 | 위도 **32.011788°**, 경도 **126.000000°** 유지 | Yaw 180° = 정남 → 자오선 추종. 자오선 곡률반경 M+h 로 수치적분한 값 |
| 대공 고도 | **300 m** 유지 | 수평 비행 |
| 플랫폼 | 전 구간 불변 | V = 0 |

> 단순 폐형식으로 `Δφ = s/(M+h)` 를 쓰면 32.011789°, `s/M` 을 쓰면 32.011784° 가 나온다. 둘의 차이 0.57 m 는 고도 300 m 를 빼먹은 만큼이다(`s·h/M`). 같은 각도를 돌아도 300 m 위에서는 그만큼 더 긴 길을 간다.
>
> **거리로 판정할 때도 같은 함정이 있다.** 시작–끝 위경도로 잰 지표면 측지선은 대공 표적에서 12 000 m 가 아니라 **11 999.433 m** 다. `(1 + h/M) = 1.0000472` 를 곱해야 12 000.000 m 가 된다(대함 표적은 h = 0 이라 1 800.000 m 그대로). 고도와 무관한 기준이 필요하면 **스텝마다 움직인 ECEF 거리의 합**을 V·t 와 대조한다. (참고: 이 경로의 ECEF 직선거리는 대함 1 800.000 m, 대공 11 999.998 m 로 호 길이와 mm 단위로 일치한다.)

### 기동 케이스 (별도 검증)

기동 구간을 넣었을 때의 판정 기준.

| 항목 | 이론값 |
|---|---|
| 선회 각속도 | ω = n·g / V |
| 선회 반경 | R = V² / (n·g) — 예: V = 200, n = 1 → **4 078.9 m**. 실제 출력에 원을 맞추면 위도에 따라 이보다 조금 작거나 크게 나온다(위도 32°에서 남향 출발 −1.39 m, 북향 출발 +1.40 m, 적도 +0.004 m). Yaw 를 그 지점의 북쪽 기준으로 재는데 그 북쪽이 표적을 따라 돌아가기 때문이며(자오선 수렴), 적분 오차가 아니다 |
| 선회 주기 | T = 2πV / (n·g) — 예: V = 200, n = 1 → **128.14 s** |
| 적분 방식 비교 | 같은 조건에서 Euler 는 궤적이 옆으로 밀려 위치 오차가 최대 **V·Δt = 20 m**(60초 시점 19.9 m). 중점법은 **0.008 m** |
| Roll 기동 | 궤적은 직진 그대로, roll 각만 변한다 |

### 검증 절차

```
1. 명세 시나리오로 실행 → CSV 저장
2. 스텝마다 움직인 ECEF 거리의 합 → V·t 와 대조
   (표본 0 / 600 의 LLA 로 측지선 거리를 잴 때는 (1 + h/M) 을 곱한 뒤 대조)
3. 전 구간 |V| 표준편차 확인 (0 이어야 한다)
4. 대함 위도·대공 경도의 변동폭 확인 (0 이어야 한다)
5. 기동 케이스 : 선회 구간 점들에 원 피팅 → 반경을 V²/(n·g) 와 대조 (위도 32°에서 0.04 % 이내)
6. Δt 를 0.1 → 0.05 로 줄여 재실행 → 오차가 약 1/4 로 줄면 전역 2차 정확도 확인
```
