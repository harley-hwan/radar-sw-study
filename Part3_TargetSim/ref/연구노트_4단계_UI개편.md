# Part3 표적 궤적 모의 — 연구 노트 4단계 (UI 개편)

- 단계: MFC UI 전면 개편 — 화면 구성·조작 방식을 새로 짬 (2026-09-18 커밋 4a70a98, 같은 날 정리 반영은 커밋 전)
- 대상 코드 (`Part3_TargetSim/src/TargetSim/TargetSimUI/`)
  - 신규: `GridCtrl.h/.cpp` (칸을 바로 고치는 표), `Scenario.h/.cpp` (편집 모델 `CScenario` 와 실행 결과 `CSimResult`: 프리셋·검증·시나리오 파일·결과 버퍼·CSV)
  - 재작성: `TargetSimUIDlg.h/.cpp` (대화상자), `TrajectoryPlot.h/.cpp` (GDI+ 그림, 끌어서 편집)
  - 확장·개명: `UiNumber_JH` → `UiCommon.h/.cpp` (숫자 문자열 함수 + 색·배율), `TargetSimUI.cpp` (GDI+ 시작·종료)
  - 파일 이름의 `_JH` 는 참고 소스와 이름이 겹치는 Core 파일에만 남기고 UI 파일에서는 뗐다. UI 파일은 4단계보다 두 쌍(`GridCtrl`, `Scenario`) 늘었다.
  - `Resource.h`, `TargetSimUI.rc` (크기 조절 되는 대화상자 760×470 DLU), `TargetSimUI.vcxproj/.filters` (새 파일 등록, DPI 인식 매니페스트)
  - Core(`TargetSimCore`)는 고치지 않았다. 입력 허용 범위, 검증 순서, 결과 표·CSV 서식도 4단계 그대로다.
- 수치는 모두 x64 빌드 실측값이다. 시간은 이 PC 한 대의 값이라 참고용이다.
- **목적 / 방법 / 결과 / 한계** 순서로 적었다. 4단계 노트(`연구노트_4단계.md`)는 기록으로 남기고, 그 노트의 화면 구성·조작·컨트롤 ID 설명은 이 노트가 대신한다.

## 목적

1. 4단계 UI 를 써 보고 나온 불편을 없앤다.
   - 값을 전부 손으로 쳐 넣어야 했다.
   - 표적을 콤보에서 하나씩 골라야 그 표적의 값이 보여서, 표적 1·2·3 의 설정이 한눈에 들어오지 않았다.
   - 고정 크기 회색 대화상자라 125 % 이상 배율에서 흐리고 작은 화면에서는 넘쳤다.
2. 구조는 단순하게 유지한다. 화면은 "위 막대 / 왼쪽 입력 / 오른쪽 출력 / 아래 상태 줄" 넷으로만 나눈다.
3. 계산 결과는 달라지면 안 된다. 명세 시나리오 CSV 가 고치기 전과 바이트 동일해야 한다.

## 방법

### 화면 구성

| 영역 | 내용 |
|---|---|
| 위 막대 | [시나리오 ▼] (프리셋 3종, 파일 열기·저장), 시간(증감 버튼), 간격(목록 + 직접 입력), 시나리오 이름과 "(수정됨)" 표시 |
| 왼쪽 위 — 플랫폼·표적 | 플랫폼과 표적 전부를 한 표에 둔다. 행 = 객체, 열 = 위도·경도·고도·속력·Roll·Pitch·Yaw·기동 구간. 행마다 색 표식(그림의 궤적 색과 같음), 마지막 칸은 0 ~ 시뮬레이션 시간에 기동 구간을 축 색 막대로 그린 띠 |
| 왼쪽 아래 — 기동 | 위 표에서 고른 표적의 기동. 열 = 축(목록)·G·시작·종료 + 계산해서 보여 주는 회전각·선회 반경 |
| 오른쪽 위 — 그림 | 동–북 평면(등축척)과 고도–시각. 가로가 넉넉하면 나란히, 좁으면 위아래. 아래에 재생·배속·시각 슬라이더 |
| 오른쪽 아래 — 결과 | LLA 표(가상 리스트, 4단계와 같은 열), [CSV 저장...] (Ctrl+S) |
| 상태 줄 | 실행 결과·오류·안내를 색으로 구분해 한 줄로 |

- 배치는 `WM_SIZE` 에서 직접 계산한다 (`f_Layout`). 처음 1400×880, 최소 1180×720 (96 DPI 기준, 화면이 더 작으면 화면에 맞춤). 표적 수만큼만 객체 표 높이를 쓰고 나머지를 기동 표에 준다.
- 시스템 DPI 인식 매니페스트를 켜고 치수를 모두 `f_Ui_Scale(px, dpi)` 로 잡았다.
- 카드(흰 둥근 사각형)는 대화상자의 `OnEraseBkgnd` 에서 그리고, 글자·슬라이더 배경은 `OnCtlColor` 로 맞췄다.

### 입력을 줄이는 장치

- 표에서 바로 고친다 (`CGridCtrl`: `CListCtrl` 을 전부 커스텀 드로우하고 칸 위에 편집칸·증감 버튼·목록을 띄움).
  - 편집 열기: 선택된 칸을 다시 누르거나 두 번 누름, F2·Enter·Space, 또는 숫자를 그냥 침 (그 글자로 편집이 열림).
  - 값 조절: ▲▼ 버튼, ↑↓ 키, 마우스 휠. Ctrl 을 누르면 10 배. 증감 폭은 위도·경도 0.001°, 고도 10 m, 속력 1 m/s, 각 1°, G 0.1, 기동 시각 = 간격 dt (그래서 증감으로는 dt 정수배를 벗어나지 않는다). 허용 범위 끝에서 멈춘다.
  - 증감은 편집을 닫지 않고 바로 반영되어, 값을 굴리는 동안 그림이 따라 움직인다.
  - Enter 확정, Esc 되돌림(증감으로 이미 바뀐 값도 편집 열기 전으로), Tab / Shift+Tab 은 다음·이전 편집 칸(행 끝에서 다음 행).
  - 기동 축은 한 번 눌러 목록에서 고른다.
- 그림에서 끈다 (`CTrajectoryPlot`).
  - 표적 시작점을 끌면 초기 위도·경도가 바뀐다. 화면 점 → 플랫폼 기준 NED → ECEF → LLA (`f_Trans_Ned_To_Ecef`, `f_Trans_Ecef_To_Lla`), 소수 6 자리(약 0.1 m). 4 px 넘게 움직여야 끌기로 보고, 끄는 동안은 축척을 고정한다.
  - 고른 표적의 기수 손잡이를 돌리면 초기 Yaw 가 1° 단위로 바뀐다.
  - 고도 패널을 누르거나 끌면 보는 시각이 바뀐다.
- [표적 추가] 는 고른 표적의 값을 물려받아 위도만 0.01° 옮겨 만들고, [복제] 는 기동까지 복사한다. [기동 추가] 는 직전 기동의 종료 시각에서 시작하는 10 s 짜리 Yaw 1.0 G 를 채워 넣는다. 시뮬레이션 시간이 남아 있으면 거기서 자르고, 남아 있지 않으면 시간을 넘는 채로 넣어 종료 칸을 붉게 표시한다 (처음에는 넣지 않았는데, 30 개까지 추가되어야 한다는 지적으로 바꿨다).
- 프리셋 3종: 명세 시나리오, 기동 시연(선회·상승·Roll), 다표적 접근(표적 6). 시나리오는 글자 파일(`.tsim`)로 저장하고 연다 (Ctrl+O). 읽다가 실패하면 편집 중이던 시나리오를 그대로 둔다.

### 실행 방식

- 고칠 때마다 자동으로 다시 실행한다. 직전 실행이 40 ms 안에 끝났으면 바로, 아니면 입력이 250 ms 멎은 뒤에 한 번. 실행 버튼은 없다 (처음에는 20000 스텝을 넘으면 [실행] 을 기다리게 했는데, 버튼의 쓸모가 보이지 않는다는 지적으로 뺐다. 최악 부하도 0.8 s 라 자동 실행으로 충분하다).
- 입력 오류는 메시지 상자 대신 해당 칸을 붉게 칠하고 상태 줄에 위치와 이유를 적는다. 그림과 표는 마지막으로 성공한 결과를 그대로 보인다. 다른 표적의 기동 오류는 객체 표의 그 표적 기동 구간 칸에 표시한다. 포커스는 옮기지 않는다.
- 검증·실행 절차 자체는 4단계와 같다: 문자열 → `f_Num_Parse` → UI 범위 검사 → `f_Tgt_ValidateConfig` → (실패 시 탐침으로 위치 찾기) → `f_Tgt_InitSim` / `f_Tgt_StepSim` → 유한성 확인 → 성공했을 때만 결과 교체. 코드는 대화상자에서 `CScenario::f_BuildConfig` 와 `CSimResult::f_Run` / `f_Commit` 으로 옮겼다.
- 시나리오 메뉴의 항목은 `WM_COMMAND` 로 받는다 (`ON_COMMAND_RANGE` 프리셋, `ON_COMMAND` 열기·저장).

### 검증 방법 (솔루션 밖 임시 도구)

- UI 자동화: Python ctypes. 앱을 **화면에 보이지 않는 별도 데스크톱**(`CreateDesktop` + `STARTUPINFO.lpDesktop`)에 띄우고 메시지로 조작한다. 쓰고 있는 화면·마우스·키보드를 건드리지 않는데, 앱은 그 데스크톱의 활성 창이라 편집칸·목록·메뉴·파일 대화상자가 모두 동작한다. 캡처는 `PrintWindow`.
- 실제 마우스 입력으로는 기동 축 목록(한 번 눌러 열림 → 항목 선택)과 숫자 칸(두 번째 클릭에 편집 열림)만 한 차례 확인했다.
- 정적 점검: MSBuild 경고 수, MSBuild 코드 분석(`RunCodeAnalysis`, NativeRecommendedRules), 규칙 점검 스크립트(기본형·블록 주석·doxygen·다중 return·else 없는 else-if·함수형 매크로), 줄바꿈·BOM 바이트 확인.
- 코드 리뷰: 에이전트 3개가 관점별(Win32·MFC 정확성 / 데이터 흐름·UX 경계 / 코딩 규칙)로 읽었다. 지적은 코드로 다시 확인한 뒤 고치고, 고친 것마다 자동화 항목이나 캡처로 확인했다.

## 한계

- 실행은 여전히 UI 스레드에서 동기로 돈다. 최악 부하에서 값을 고칠 때마다 Release 0.7 ~ 0.8 s (Debug 2.8 s) 동안 입력이 멈추고 진행 표시·취소가 없다. 40 ms / 250 ms 기준은 명세에 없는 판단이다.
- 되돌리기(Undo)가 없다. Esc 는 열려 있는 칸만 되돌린다. 표적·기동 삭제는 확인 없이 바로 지운다.
- 그림에서 끌어 놓은 위치는 플랫폼 접평면의 점을 위경도로 바꾼 값이다. 고도가 높은 표적은 놓은 자리와 (1 + h/R) 만큼 어긋난다 (15 km 거리·고도 3000 m 에서 약 7 m, 화면에서는 1 px 미만).
- 시작점이 한곳에 몰리면(예: 같은 자리에서 0.01° 씩 복제한 표적 8 개) 이름표가 겹친다. 초기값이 같은 표적은 여전히 겹쳐 하나로 보인다.
- DPI 는 시스템 배율만 따른다 (모니터마다 다른 배율은 미지원). 96 DPI 에서만 확인했다. 화면이 최소 크기보다 작으면 창을 화면에 맞추지만 그때는 표 글자가 잘릴 수 있다.
- 자동화는 메시지 기반이다. 팝업 메뉴는 게시한 방향키를 메뉴 루프가 받지 않는 실행이 가끔 있어(메뉴가 열린 채 남음), 그 실행에서는 "메뉴 항목 → 처리기" 1 항목을 미실행으로 넘긴다. 실제 마우스로는 목록·숫자 칸만 확인했다. `PrintWindow` 캡처는 창틀이 고전 모양으로 나온다(클라이언트 영역은 같다).
- `.tsim` 은 이 UI 만 읽는 글자 파일이다 (머리글 `TargetSim scenario 1`, `duration=`·`step=`·`platform=`·`target=`·`maneuver=축,G,시작,종료`). 값은 화면의 글자 그대로라 잘못된 값도 저장되고, 열 때는 형식만 보고 값 검사는 실행 단계에 맡긴다.
- 줄바꿈: 작업 트리는 CRLF 인데 루트 `.gitattributes` 는 `*.cpp`·`*.h` 를 eol=lf 로 정규화한다 (2·3·4단계와 같은 미결).
- 입력 허용 범위·dt 정수배 강제·스텝당 회전각 30° 제한(4단계), 3단계 부록 A 결정 10 건은 여전히 사용자 확정 전이다.
