### 2단계에서 정해진 동작

3절에서 바꾸라고 명시한 것 외에는 바꾸지 않는다.

- 적분은 중점법이다. 스텝 중앙 자세로 속도를 구해 위치를 옮기고, NED 기준 위경도는 스텝 시작 값을 쓴다.
- 기동 각속도 `omega = gravityValue * G_FORCE / headingSpeed` 를 TurnType 축의 오일러각 변화율로 적용한다.
- 기동 판정은 `startTime <= simTime + TGT_TIME_EPSILON < endTime`, `TGT_TIME_EPSILON = 1e-6 s` 이다 (`.c` 내부 `#define`).
- 실패하면 상태는 바뀌지 않는다 (지역 사본에서 계산한 뒤 한 번에 반영).
- `f_Tgt_InitState` 는 자세각을 `f_Coord_WrapAngle` 로 정규화한다.
- `f_Tgt_StepTarget` 은 `headingSpeed <= 0` 을 `TGT_ERR_SPEED` 로 거부한다.
  → **정지 플랫폼(0 m/s)은 지금 전파할 수 없다.**
- `f_Tgt_ValidateConfig` 는 플랫폼을 검사하지 않는다.

### 이미 정해진 규약

- 좌표계: Body(x 전방, y 우현, z 하방) / NED(x 북, y 동, z 하) / ENU(x 동, y 북, z 상)

## 3. 이번 작업 — 3단계: 시나리오 실행기

과제 명세 2절 "시뮬레이션 조건" 의 **실행** 부분이다.
설정(`ST_SimConfig`) 하나로 플랫폼과 표적 전체를 0 ~ durationTime 동안 stepTime 간격으로 전파한다.
결과 출력(LLA 표·파일)은 4단계, 그림은 5단계에서 한다.

### 설계 개요

- Core 는 **가장 최근 표본 하나**만 갱신한다. 표본 전체(명세 조건 601개)는 호출자(4단계 UI)가 스텝마다 복사해 보관한다.
  - Core 는 malloc 을 쓸 수 없고, 601 × 1,160 B ≈ 0.7 MB 는 스택에 둘 수 없다.
- 초기화할 때 설정을 상태 안에 복사해 두고, 스텝 함수는 상태 하나만 받는다.
  - 초기화 뒤 원본 설정을 바꿔도 진행 중인 실행과 섞이지 않는다.
- 플랫폼은 표적과 같은 중점법 본체를 각속도 0 으로 통과한다.
  - 본체 경로에 속도로 나누는 연산이 없어 속도 0 이 안전하다.
- 시각은 누적 대신 `스텝 번호 × stepTime` 으로 매기고, 종료 판정은 정수로만 한다.
  기동 판정 시각도 표본 안의 객체 simTime 이 아니라 스텝 번호에서 계산한 시각을 넘긴다.

### 대상 파일

- `TargetSimCore/include/TargetSim_JH.h`
- `TargetSimCore/src/TargetSim_JH.c`

### 헤더에 추가할 것

기존 구조체와 선언 4개는 바꾸지 않는다 (`sizeof` 104 / 1,024 / 10,320 유지). 단 `ST_TargetState` 주석의 "LLA 는 출력용" 은 틀렸으므로 "LLA 는 출력과 다음 스텝의 NED 기준으로 함께 보관한다" 로 고친다 (`f_Tgt_Propagate` 가 스텝 시작 LLA 를 NED 기준으로 쓴다).

```c
#define TGT_MAX_STEP_NUM			100000			// [결정 필요] 스텝 수 상한
#define TGT_MIN_STEP_TIME			1.0e-3			// [결정 필요] stepTime 하한 [s]

typedef enum
{
	TGT_OK = 0,
	TGT_ERR_NULL,
	TGT_ERR_TARGET_NUM,
	TGT_ERR_MANEUVER_NUM,
	TGT_ERR_TIME,
	TGT_ERR_SPEED,
	TGT_ERR_TURN_TYPE,
	TGT_ERR_MANEUVER_OVERLAP,
	TGT_ERR_COORD,
	TGT_ERR_SIM_STATE,			// 초기화되지 않았거나 내용이 서로 맞지 않는 ST_SimState
	TGT_ERR_SIM_END				// 마지막 표본 뒤의 호출 [결정 필요]
} EN_TgtStatus;

// 한 시각의 플랫폼·표적 상태. 호출자는 스텝마다 이 구조체를 복사해 보관한다.
typedef struct
{
	FLOAT64				simTime;						// [s] nStepIndex * stepTime
	INT32				nStepIndex;						// 0 ~ nStepNum
	INT32				nTargetNum;
	ST_TargetState		st_Platform;
	ST_TargetState		st_Target[TGT_MAX_TARGET_NUM];	// 설정과 같은 인덱스, nTargetNum 이후 칸은 0.0
} ST_SimSample;

// 시나리오 진행 상태. 설정 사본을 함께 보관한다.
typedef struct
{
	INT32				nStepNum;						// 표본 수는 nStepNum + 1
	ST_SimSample		st_Sample;						// 가장 최근 표본
	ST_SimConfig		st_Config;
} ST_SimState;

TSCORE_API EN_TgtStatus		f_Tgt_InitSim(ST_SimState *st_Sim, const ST_SimConfig *st_Config);
TSCORE_API EN_TgtStatus		f_Tgt_StepSim(ST_SimState *st_Sim);
```

함수 이름, 열거형, 상수값은 제안이다. 더 나은 안이 있으면 바꾸되 **API 스타일과 명명 규칙은 유지하고, 바꾼 이유를 보고할 것.**

### 구현할 기능

#### (a) 스텝 수 계산 (static)

```c
static INT32 f_Tgt_GetStepNum(const ST_SimConfig *st_Config);
```

유효하면 1 ~ `TGT_MAX_STEP_NUM`, 아니면 0 을 돌려준다. `TGT_STEP_RATIO_TOLERANCE = 1.0e-6` 은 `.c` 내부 `#define` 으로 둔다.

```
1) (stepTime >= TGT_MIN_STEP_TIME) && (durationTime >= stepTime) 가 참일 때만 2)~4). 아니면 0
     긍정형이라 NaN 은 여기서 걸린다
2) ratio   = durationTime / stepTime
3) nearest = floor(ratio + 0.5)
4) (nearest <= (FLOAT64)TGT_MAX_STEP_NUM) && (fabs(ratio - nearest) <= TGT_STEP_RATIO_TOLERANCE)
     이면 (INT32)nearest, 아니면 0
```

- durationTime 이 stepTime 의 정수배가 아니면 거부한다 `[결정 필요]`. 끝을 버리거나 마지막 스텝을 짧게 만들지 않는다.
- 판정 예
  - (60, 0.1) → 600
  - (0.3, 0.1) → 3 (0.3 / 0.1 = 2.9999999999999996)
  - (60.05, 0.1) → 0 (정수배 아님)
  - (60, 1e-4) → 0 (stepTime 하한 미달)

#### (b) `f_Tgt_ValidateConfig` 수정 (시그니처 유지)

기존 시간 분기 `(stepTime <= 0.0) || (durationTime < stepTime)` 를 아래 두 분기로 바꾼다.
검사 순서는 NULL → 표적 수 → 시간 → (신규) 플랫폼 속도 → 표적별 검사다.

```
- f_Tgt_GetStepNum(st_Config) < 1              → TGT_ERR_TIME
- !((st_Platform.headingSpeed >= 0.0) && (st_Platform.headingSpeed < HUGE_VAL))
                                                → TGT_ERR_SPEED     [결정 필요] 0 허용, 음수·NaN·+Inf 거부
```

새로 거부되는 설정은 다음과 같다. 이 조건에 해당하지 않는 설정의 판정은 2단계와 같아야 한다 (이 조건과 표적별 오류가 함께 있으면 검사 순서에 따라 `TGT_ERR_TIME` / `TGT_ERR_SPEED` 로 바뀐다. 검증 6 참조).

- 0 < stepTime < 1e-3 s `[결정 필요]`
- durationTime 이 stepTime 의 정수배가 아님
- 스텝 수 100,000 초과 `[결정 필요]`
- durationTime 또는 stepTime 이 NaN, durationTime 이 +Inf (durationTime 이 유한하면 stepTime +Inf 는 2단계에서도 거부됐다. 둘 다 +Inf 인 조합은 새로 거부된다)
- 플랫폼 속도 음수 / NaN / +Inf (+Inf 를 통과시키면 오류 코드 없이 NaN 표본이 나온다)

기존 검사(표적 속도 `<= 0.0`, 기동 startTime·endTime, `f_Tgt_StepTarget` 의 `stepTime <= 0.0`)는 NaN 거부형으로 바꾸지 않는다 `[결정 필요]`.

#### (c) 중점법 본체 분리 (static)

```c
static EN_TgtStatus f_Tgt_Propagate(ST_TargetState *st_State, const ST_CoordAtt *st_Rate,
									FLOAT64 headingSpeed, FLOAT64 stepTime, FLOAT64 nextTime);
static EN_TgtStatus f_Tgt_StepTargetAt(ST_TargetState *st_State, const ST_TargetInit *st_Target,
									   FLOAT64 stepTime, FLOAT64 curTime, FLOAT64 nextTime);
static EN_TgtStatus f_Tgt_StepPlatformAt(ST_TargetState *st_State, const ST_PlatformInit *st_Platform,
										 FLOAT64 stepTime, FLOAT64 nextTime);
static VOID			f_Tgt_ClearState(ST_TargetState *st_State);
```

- `f_Tgt_Propagate`
  - 옮기는 범위는 현재 `f_Tgt_StepTarget` 의 중점법 주석(`// 중점법(RK2): …`)과 `halfStep = 0.5 * stepTime;` 부터 상태 반영 `if / else` 까지다 (지역 변수 `enCoord`, `st_Next`, `st_AttMid`, `st_VelMid`, `st_Delta`, `halfStep` 선언도 함께 옮긴다). **연산 순서 그대로** 옮긴다.
  - 부동소수 식에서 바뀌는 것은 아래 셋뿐이다.
    - `st_Rate.roll / pitch / yaw` → `st_Rate->roll / pitch / yaw`
    - `st_Target->headingSpeed` → `headingSpeed`
    - `st_Next.simTime = st_State->simTime + stepTime` → `st_Next.simTime = nextTime`
  - 상태 코드: 원래는 `f_Tgt_GetAttRate` 가 채운 `enStatus`(TGT_OK)를 이어받았다. 분리한 함수에서는 상태를 반영하는 `if (enCoord == COORD_OK)` 분기에 `enStatus = TGT_OK;`, else 분기에 `enStatus = TGT_ERR_COORD;` 를 **양쪽 모두 대입**한다 (선언에서 초기화하지 않는다).
- `f_Tgt_StepTargetAt`: `f_Tgt_GetAttRate(&st_Rate, st_Target, curTime)` → 성공하면 `f_Tgt_Propagate`
- `f_Tgt_StepPlatformAt`: 각속도 0 으로 `f_Tgt_Propagate`
- `f_Tgt_ClearState`: FLOAT64 필드 13개에 0.0 대입
- 공개 `f_Tgt_StepTarget`: NULL 검사 → `stepTime <= 0.0` 검사(2단계 형태 유지) →
  `f_Tgt_StepTargetAt(st_State, st_Target, stepTime, st_State->simTime, st_State->simTime + stepTime)`
- 파일 배치는 기존처럼 **전방 선언 없이 피호출 함수를 먼저 정의**한다.
  - `f_Tgt_GetStepNum`: `f_Tgt_GetVelEcef` 뒤, `f_Tgt_ValidateConfig` 앞
  - `f_Tgt_Propagate` → `f_Tgt_StepTargetAt` → `f_Tgt_StepPlatformAt` → `f_Tgt_ClearState`: `f_Tgt_InitState` 뒤, `f_Tgt_StepTarget` 앞
  - `f_Tgt_InitSim` → `f_Tgt_StepSim`: `f_Tgt_StepTarget` 뒤, `f_Tgt_StatusStr` 앞

#### (d) 시나리오 초기화

```c
EN_TgtStatus f_Tgt_InitSim(ST_SimState *st_Sim, const ST_SimConfig *st_Config);
```

```
1) NULL 검사
2) enStatus = f_Tgt_ValidateConfig(st_Config). 실패하면 그 코드를 그대로 반환
3) 2) 가 성공한 블록 안에서 (아래 4) 까지 모두 이 블록 안에 중첩)
     nStepNum = f_Tgt_GetStepNum(st_Config)             (검증을 통과했으므로 1 이상)
     지역 ST_SimSample 에 simTime = 0, nStepIndex = 0, nTargetNum 기록
     플랫폼 f_Tgt_InitState
     nTarget < nTargetNum 인 칸은 f_Tgt_InitState, 나머지 칸(~TGT_MAX_TARGET_NUM)은 f_Tgt_ClearState
     첫 실패 뒤로는 InitState 를 건너뛰고 그 코드(f_Tgt_InitState 의 반환값)를 그대로 반환
4) 같은 블록의 마지막 if (enStatus == TGT_OK) 안에서만 반영
     st_Sim->st_Config = *st_Config,  st_Sim->nStepNum = nStepNum,  st_Sim->st_Sample = 지역 표본
     (st_Config 가 &st_Sim->st_Config 인 경우도 안전해야 한다)
```

- 실패하면 `*st_Sim` 에 아무것도 쓰지 않는다. 따라서 **재초기화가 실패하면 이전 실행이 그대로 남아** `f_Tgt_StepSim` 으로 계속 진행된다.
  호출자 계약: `ST_SimState` 를 0 으로 채워 두고, `f_Tgt_InitSim` 이 `TGT_OK` 가 아니면 `f_Tgt_StepSim` 을 부르지 않는다 (보고서에 이 계약을 적을 것).
  `f_Tgt_StepSim` 은 설정 사본의 유효성과 nStepNum·nStepIndex·nTargetNum 의 일치만 검사한다. 표본 안의 위치·자세·LLA 값, 쓰지 않는 칸, 서로 맞게 함께 바꾼 설정·스텝 번호는 검사하지 않으므로, 호출자는 `f_Tgt_InitSim` / `f_Tgt_StepSim` 외에는 `ST_SimState` 에 쓰지 않는다.
- 진행 중이거나 끝난 상태에 다시 부르면 처음부터 다시 시작한다 (리셋).

#### (e) 시나리오 1스텝

```c
EN_TgtStatus f_Tgt_StepSim(ST_SimState *st_Sim);
```

```
1) NULL 검사
2) 사본 설정 재검증: f_Tgt_ValidateConfig(&st_Sim->st_Config) 실패 → TGT_ERR_SIM_STATE      [결정 필요]
     공개 구조체라 호출 사이에 바뀔 수 있으므로, 배열 인덱스와 나눗셈의 근거를 이번 호출 안에서 다시 세운다 (값의 물리적 타당성은 보장하지 않음)
3) 일치 검사, 하나라도 어긋나면 TGT_ERR_SIM_STATE
     f_Tgt_GetStepNum 결과 == st_Sim->nStepNum
     0 <= st_Sample.nStepIndex <= nStepNum
     st_Sample.nTargetNum == st_Config.nTargetNum
4) st_Sample.nStepIndex == nStepNum → TGT_ERR_SIM_END (상태 불변)      [결정 필요]
5) 진행 (아래 6) 까지 모두 이 else 블록 안에 중첩)
     nNextIndex = nStepIndex + 1
     curTime    = (FLOAT64)nStepIndex * stepTime        (nStepIndex 는 지역 변수에 복사한 값)
     nextTime   = (FLOAT64)nNextIndex * stepTime
     지역 ST_SimSample 사본에서
       플랫폼: f_Tgt_StepPlatformAt(…, stepTime, nextTime)
       표적 0 .. nTargetNum-1: f_Tgt_StepTargetAt(…, stepTime, curTime, nextTime)
     첫 실패 뒤로는 건너뛰고 그 코드를 반환
6) 같은 블록의 마지막 if (enStatus == TGT_OK) 안에서만
     사본에 nStepIndex = nNextIndex, simTime = nextTime 을 기록하고 st_Sim->st_Sample 에 반영
     (nStepNum · nNextIndex · curTime · nextTime 을 계산한 블록 밖에서 읽지 말 것. 연속 블록으로 쓰면 C4701)
```

- 한 표본 안에서 객체마다 시각이 섞이면 안 된다 (원자성).
- 표적 루프 상한은 지역 변수에 복사한 nTargetNum 을 쓸 것 (Rule 14.2).

#### (f) `f_Tgt_StatusStr`

`TGT_ERR_SIM_STATE`, `TGT_ERR_SIM_END` case 를 기존 형식(대입 후 break)으로 추가한다.

### 알고 있어야 할 동작

- **정지 플랫폼의 LLA** — 위치 증분이 0 이라 ECEF 는 비트 단위로 그대로다.
  그러나 LLA 는 매 스텝 Bowring 역변환으로 다시 구하므로, 표본 0(입력값)과 표본 1 이후의 고도가 약 −9.3e-10 m 다를 수 있다 (위경도 차 0).
  Core 에서 보정하지 말고 실측값을 보고할 것 `[결정 필요]`.
- **ε 유지** `[결정 필요]` — 곱으로 시각을 매겨도, 10진 표기로 입력한 기동 시각과 비교하면
  dt 0.3 s (60 s, 경계 200개) 는 48개, dt 0.7 s (420 s, 경계 600개) 는 254개가 1 ulp 아래로 떨어진다.
  `TGT_TIME_EPSILON` 값은 그대로 두고, 주석만 "누적 시각과 격자 시각 모두" 에 해당하도록 고칠 것.
- **격자 밖 기동 시각** `[결정 필요]` — dt 0.1 s 에서 startTime 10.05 s 인 기동은 다음 격자(10.1 s)부터 켜지고, 한 스텝보다 짧은 기동은 무시될 수 있다.
  이번 단계에서는 거부하지 말고 검증 7 에서 동작을 보고할 것.

## 4. 검증 (반드시 수행하고 수치를 보고할 것)

Core 는 `printf` 를 쓸 수 없으므로(Rule 21.6), 검증용 콘솔 코드는 **임시 파일로 작성해 직접 컴파일·실행**하고, **솔루션에는 추가하지 말 것.**
결함 주입이 필요한 검증은 `TargetSim_JH.c` 를 임시 폴더로 복사해서 한다 (저장소 파일 수정 금지). 검증이 끝나면 임시 파일은 삭제한다.

### 시나리오 (과제 명세 2절 및 2단계 시험)

- 기본: 시뮬레이션 60 s, 갱신 간격 0.1 s (600 스텝, 표본 601개)
- 플랫폼: Lat 32.0°, Lon 126.0°, Alt 0 m, 속도 0 m/s, 자세 0
- 대함 표적: Lat 32.125°, Lon 126.03°, Alt 0 m, V 30 m/s, (Roll 0°, Yaw 270°, Pitch 0°), 기동 없음
- 대공 표적: Lat 32.12°, Lon 126.0°, Alt 300 m, V 200 m/s, (Roll 0°, Yaw 180°, Pitch 0°), 기동 없음
- **1 G Yaw 선회**: 대공 표적에 `TGT_TURN_YAW`, `gravityValue = 1.0`, `startTime = 0`, `endTime = 60`
- **Δt 0.001 s 선회**: 같은 선회를 0.001 s 로 60,000 스텝. Euler·중점법 끝 위치 오차의 기준해
- **원 맞춤 반경**: 대공 시작점 기준 로컬 NED 로 바꾼 601 표본의 수평 좌표(N, E)에 최소자승 원(Kasa 방식)을 맞춘 반경
- **Euler (하네스 안에서만 구현)**: 위치는 스텝 시작 상태의 ECEF 속도로 적분, 자세는 한 스텝 전체 각속도로 갱신, 속도는 스텝 끝 자세·위경도로 다시 계산. 기동 판정·좌표 변환은 Core 와 같게

### 착수 전 기준 덤프 (필수)

수정하기 **전에** 현재(2단계) 코드로 Debug / Release DLL 을 빌드한다.
대함·대공 직진, 1 G Yaw 선회, Δt 0.001 s 선회에 대해 매 스텝 `ST_TargetState` 13개 필드를 `%a` (또는 `%.17g`) 로 저장한다.
`f_Tgt_ValidateConfig` 오류 판정표도 저장한다.

### 검증 항목

1. **2단계 비트 회귀**
   - 리팩터 후 `f_Tgt_InitState` + `f_Tgt_StepTarget` 로 같은 덤프를 떠서 기준 덤프와 텍스트 차이 0 (Debug / Release 각각)
   - 1절의 2단계 수치 재현
2. **명세 시나리오** (60 s / 0.1 s, 플랫폼 + 대함 + 대공)
   - `f_Tgt_InitSim` OK, `nStepNum` = 600, `f_Tgt_StepSim` 600회 모두 `TGT_OK` → 표본 601개
   - 표본 k 의 `nStepIndex` = k, `simTime` 과 모든 객체의 `simTime` 이 `(FLOAT64)k * 0.1` 과 비트 동일 (마지막 60.0)
   - 601번째 `f_Tgt_StepSim` → `TGT_ERR_SIM_END`, 호출 전후 상태 동일 (memcmp)
   - 대함·대공 끝 좌표가 1절 수치와 같음
3. **실행기 = 단독 루프**
   - 같은 표적을 `f_Tgt_StepTarget` 600회로 돌린 결과와 실행기 표본의 위치·속도·LLA·자세 12개 값이 모든 스텝에서 비트 동일
     (`simTime` 만 다름: 단독 60.000000000000583, 실행기 60.0)
   - 1 G Yaw 선회 설정으로도 비교
4. **플랫폼**
   - V = 0: 601 표본 모두 ECEF 위치가 표본 0 과 비트 동일, 속도 세 성분의 크기 0, 자세 비트 불변.
     속도에는 −0.0 이 섞일 수 있으므로 `fabs` 로 확인하고 +0.0 과 memcmp 로 비교하지 말 것.
     표본 0 과 표본 1 이후의 LLA 차이를 수치로 보고 (기대: 위경도 차 0, 고도 차 약 −9.3e-10 m)
   - V > 0: 플랫폼을 대함 초기값(30 m/s, yaw 270°)으로 두면 기동 없는 대함 표적과 궤적이 비트 동일
5. **스텝 수·시간 판정표** (`f_Tgt_InitSim` 결과로 확인)
   - OK: (60, 0.1) → 600, (60, 0.3) → 200, (0.3, 0.1) → 3, (0.1, 0.1) → 1, (100, 0.001) → 100000
   - `TGT_ERR_TIME`: (60, 0.7), (60.05, 0.1), (100.001, 0.001), (60, 1e-4), (0.05, 0.1), (60, 0), (60, −0.1),
     durationTime·stepTime 각각 NaN / +Inf
   - 실패한 경우 미리 채워 둔 `ST_SimState` 가 바뀌지 않음 (memcmp)
6. **ValidateConfig 신규 분기와 판정 순서**
   - 플랫폼 속도 −1 / NaN / +Inf → `TGT_ERR_SPEED`, 0 / −0.0 / 1 → `TGT_OK`
   - 표적 수 오류 + 시간 오류 → `TGT_ERR_TARGET_NUM`
   - 시간 오류 + 플랫폼 속도 오류 → `TGT_ERR_TIME`
   - 시간 오류 + 표적별 오류(표적 속도 0, 기동 겹침 등) → `TGT_ERR_TIME`
   - 플랫폼 속도 오류 + 속도가 아닌 표적별 오류(기동 겹침 → `TGT_ERR_MANEUVER_OVERLAP`, TurnType 5 → `TGT_ERR_TURN_TYPE`) → `TGT_ERR_SPEED` (플랫폼 쪽)
   - 2단계 오류 판정표의 나머지 항목은 그대로
7. **기동 경계와 ε**
   - (dt, durationTime) = (0.1, 60), (0.3, 60), (0.7, 420) 에서 시험한다.
   - startTime 은 k·dt 의 **10진 표기 문자열**(예: `"10.2"`)을 `strtod` 로 읽은 값, endTime 은 (k+10)·dt 를 같은 방식으로 읽은 값으로 둔다.
     `(FLOAT64)k * dt` 곱으로 만들지 말 것 (곱이면 격자 시각과 같아져 ε 시험이 되지 않는다).
   - k = 1 .. nStepNum−10 마다 Yaw 1 G 기동 1건으로 따로 실행해, 기동이 nStepIndex k 인 스텝부터 켜지고 k+10 인 스텝부터 꺼지는지 확인한다.
   - ε = 0 으로 바꾼 임시 사본으로 같은 시험을 돌려 어긋난 k 개수를 dt 별로 보고한다
     (참고: 곱 격자가 10진 시각보다 1 ulp 작은 경계는 0.1 s 0/600, 0.3 s 48/200, 0.7 s 254/600. 시작 또는 종료 경계 하나만 걸려도 어긋나므로 기대 어긋난 k 는 0.1 s 0/590, 0.3 s 60/190, 0.7 s 274/590). 대조 빌드는 폐기한다.
   - 격자 밖 시각: (60, 0.1) 에서 startTime 10.05 s·endTime 10.25 s 인 기동과 10.05 s ~ 10.08 s 인 기동이 각각 켜지는 첫 스텝과 적용된 스텝 수를 보고한다
     (기대: 10.1 s 부터 2 스텝 / 0 스텝).
8. **오용·변조**
   - `f_Tgt_StepSim(NULL)`, `f_Tgt_InitSim(NULL, cfg)`, `f_Tgt_InitSim(sim, NULL)` → `TGT_ERR_NULL`
   - 0 으로 채운 `ST_SimState` 에 `f_Tgt_StepSim` → `TGT_ERR_SIM_STATE`
   - 10 스텝 진행 뒤 하나씩 변조하면 모두 `TGT_ERR_SIM_STATE`, 상태 불변:
     사본 nTargetNum 0 / 11, durationTime 30, stepTime 1e-4, 표적 headingSpeed 0, nStepNum + 1, nStepIndex −1 / nStepNum + 1, 표본 nTargetNum 불일치
   - 대공 표적(인덱스 1)에 Yaw 1 G 기동 1.0 ~ 3.0 s 를 넣은 설정으로 10 스텝(simTime 1.0) 진행한 뒤, 표본 안 표적 1 의 simTime 을 50.0 으로 변조하고 끝까지 진행하면 모든 호출이 `TGT_OK` 이고 모든 표본이 변조하지 않은 실행과 비트 동일 (객체 simTime 으로 판정하면 기동이 꺼져 결과가 달라진다)
9. **원자성** (임시 사본에 결함 주입)
   - 표적 인덱스 1(대공)이 nStepIndex 36 → 37 로 가는 호출에서 `TGT_ERR_COORD` 를 내게 하면, `f_Tgt_StepSim` 이 `TGT_ERR_COORD` 를 반환하고 `*st_Sim` 전체가 호출 전과 memcmp 동일 (nStepIndex 36, 플랫폼·표적 0 도 36 스텝 값)
   - 다른 실행을 진행 중인 `ST_SimState` 에 표적 3개 이상인 설정으로 `f_Tgt_InitSim` 할 때 표적 인덱스 1 의 `f_Tgt_InitState` 가 `TGT_ERR_COORD` 를 내게 하면, 그 코드를 반환하고 이전 상태 불변 (memcmp), 인덱스 2 이후 `f_Tgt_InitState` 는 호출되지 않음, 뒤이은 `f_Tgt_StepSim` 이 이전 실행을 이어감
10. **리셋·별칭·재진입**
    - 끝난 상태에 `f_Tgt_InitSim` 을 다시 부르면 첫 초기화 직후와 동일, 두 번째 실행 결과가 첫 실행과 비트 동일
    - 진행 중인 상태에 잘못된 설정으로 `f_Tgt_InitSim` → 오류 코드 반환, 상태 불변(memcmp), 이어서 `f_Tgt_StepSim` 이 이전 실행을 계속 진행함 ((d) 의 호출자 계약 근거)
    - `f_Tgt_InitSim(&sim, &sim.st_Config)` 결과가 별도 설정으로 초기화한 결과와 동일
    - 두 `ST_SimState` 를 번갈아 진행해도 각각 단독 진행과 동일
    - 쓰지 않는 표적 칸은 계속 0.0
11. **최악 부하**
    - 표적 10 × 기동 30 (겹침 없음), 스텝 100,000 으로 전 구간 `TGT_OK`
    - Release 소요 시간 보고 (매 스텝 전체 재검증 비용 판단 자료), Debug 에서 스택 문제 없음
12. **크기·열거값·문자열**
    - `sizeof`: `ST_TargetState` 104, `ST_TargetInit` 1,024, `ST_SimConfig` 10,320 그대로. `ST_SimSample`, `ST_SimState` 실측값 보고 (예상 1,160 / 11,488)
    - `TGT_OK` ~ `TGT_ERR_COORD` = 0~8 그대로, 신규 9·10
    - `f_Tgt_StatusStr` 0~10 이 열거 이름과 같고, 미정의 값은 `"TGT_ERR_UNKNOWN"`
13. **Debug = Release** — 2~12 출력(시간 측정 줄 제외)이 두 DLL 사이에서 동일
